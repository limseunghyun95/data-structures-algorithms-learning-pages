한 줄 요약
ADT는 사용자가 기대하는 연산 계약, data structure는 그 계약을 저장·유지하는 표현, algorithm은 입력을 출력으로 바꾸는 유한한 절차, program은 이를 언어·runtime·I/O·오류 처리와 함께 실행 가능하게 만든 구현이다.

1. 용어 사전

ADTAbstract Data Type. 값의 종류와 허용 연산, 연산의 의미를 정의하지만 내부 표현은 숨기는 계약.
Data structure값을 memory/storage에 배치하고 ADT 연산을 지원하는 구체적 표현과 유지 규칙.
Algorithm정의된 입력을 원하는 출력으로 변환하는 명확하고 종료 가능한 절차.
Invariant특정 경계에서 항상 참이어야 하는 조건. 자료구조 연산의 정확성을 지탱한다.
Complexity입력 크기에 따라 필요한 시간·공간이 어떻게 증가하는지 나타내는 비용 모델.
Programalgorithm과 data structure에 파싱, validation, I/O, concurrency, error handling을 결합한 실행 가능한 산출물.

3. 같은 ADT, 다른 data structure

Sequence ADT가 “끝에 추가”, “i번째 조회”, “앞에서 제거”를 제공한다고 하자. Python `list`와 `collections.deque`는 비슷한 사용 경험을 주지만 표현과 비용은 다르다.

연산Dynamic arrayDeque
끝에 추가amortized O(1)O(1)
앞에서 제거O(n), 뒤 원소 이동O(1)
임의 위치 조회O(1), locality 좋음끝에서 멀수록 비용 증가 가능

따라서 “queue에는 deque”는 암기 문장이 아니라 앞 제거가 빈번하고 임의 접근이 중요하지 않다는 workload에서 나온 결론이다. 요구 연산의 빈도와 입력 크기가 달라지면 선택도 달라질 수 있다.

4. CS Deep Dive: representation invariant

ring buffer로 bounded queue를 구현한다고 하자. 내부에는 배열, head, tail, size가 있다. 연산 전후에 다음이 항상 참이어야 한다.

  • 0 ≤ size ≤ capacity
  • 0 ≤ head, tail < capacity
  • 논리적 i번째 원소는 buffer[(head + i) % capacity]에 있다.
  • enqueue 성공 후 size는 정확히 1 증가하고, dequeue 성공 후 정확히 1 감소한다.

ADT 계약은 “가득 찬 queue에 enqueue하면 어떻게 되는가?”도 정의해야 한다. 즉시 실패, 가장 오래된 값 제거, block, timeout 중 하나를 선택하지 않으면 호출자가 신뢰할 수 있는 프로그램이 되지 못한다. data structure 정확성은 정상 입력뿐 아니라 경계 동작까지 포함한다.

5. algorithm은 자료구조와 독립적이면서도 의존적이다

BFS라는 algorithm의 핵심은 발견한 정점을 FIFO 순서로 처리하는 것이다. FIFO Queue ADT만 만족하면 이론상 구현체를 바꿀 수 있다. 하지만 queue를 dynamic array의 앞 삭제로 구현하면 전체 실행이 불필요하게 O(V²)에 가까워질 수 있다. algorithm의 복잡도 분석은 내부 ADT 연산 비용을 상수라고 무조건 가정하면 안 된다.

면접에서 한 단계 깊은 답: “BFS는 O(V+E)”라고 끝내지 말고 graph 표현이 adjacency list인지 matrix인지, queue 연산이 O(1)인지, visited set의 lookup 가정이 무엇인지 밝힌다.

6. 실무 Best Practice와 오류 처리

  • 계약 먼저: null, duplicate, ordering, overflow, capacity, concurrency 동작을 API에 명시한다.
  • invariant 검사: 개발·테스트 빌드에서 경계 연산 후 invariant를 assertion으로 검증한다.
  • 분포를 측정: 평균 입력만 benchmark하지 말고 sorted, skewed, duplicate-heavy, adversarial 입력을 포함한다.
  • Big-O 밖의 비용: allocation 수, cache locality, serialization, garbage collection, contention도 기록한다.
  • 실패를 값으로: empty pop, capacity 초과 같은 예상 가능한 실패를 모호한 sentinel보다 명시적 exception/result로 표현한다.
Benchmark 함정: 짧은 한 번의 wall-clock 측정은 interpreter warm-up, GC, CPU frequency, background load에 흔들린다. 점근 분석을 benchmark로 대체하지 말고, benchmark도 반복·분포·환경을 기록한다.

7. 30분 실습: 같은 Queue ADT 비교

from collections import deque
from time import perf_counter

N = 100_000

def run_queue(q, pop_left):
    for i in range(N):
        q.append(i)
    start = perf_counter()
    for _ in range(N):
        pop_left()
    return perf_counter() - start

items = []
print("list:", run_queue(items, lambda: items.pop(0)))

items = deque()
print("deque:", run_queue(items, items.popleft))

예상: 둘 다 FIFO 결과는 같지만 `list.pop(0)`는 남은 원소를 이동하므로 N이 커질수록 급격히 느려진다.

검증 확장: N을 10배씩 늘려 실행 시간을 표로 기록한다. 결과가 예상과 다르면 코드 오류, 머신 부하, N이 너무 작음, 구현 최적화를 가설로 나누고 다시 측정한다.

8. 대기업 면접 질문

  1. ADT와 data structure 차이는?
    외부 연산 계약과 내부 표현을 분리하고, 같은 Queue ADT를 array/ring buffer/linked list로 구현할 수 있음을 예로 든다.
  2. Big-O가 같으면 성능도 같은가?
    상수항, locality, allocation, branch prediction, input distribution, concurrency와 memory limit을 설명한다.
  3. 올바른 구현임을 어떻게 믿는가?
    pre/postcondition, representation/loop invariant, 경계·property test, 최소 반례, benchmark를 역할별로 구분한다.
