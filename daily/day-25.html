한 줄 요약
Priority Queue는 “가장 우선인 항목”을 반복 제공하는 ADT이고, binary heap은 complete array와 parent≤child라는 국소 불변식으로 peek Θ(1), push·poll Θ(log n), bottom-up build Θ(n)을 구현한다.

1. 초보자를 위한 용어 사전

Priority Queue(PQ)먼저 들어온 값이 아니라 우선순위가 가장 높은 값을 먼저 꺼내는 추상 자료형(ADT).
ADT사용자에게 보이는 연산·결과의 계약. PQ는 계약, heap은 그 구현 표현 중 하나다.

Complete binary tree마지막 level만 덜 찰 수 있고 그마저 왼쪽부터 채운 이진트리. 포인터 없이 연속 배열에 담을 수 있다.

Lazy deletion기존 entry를 즉시 찾지 않고 새 version을 넣은 뒤 pop할 때 stale entry를 버리는 방법.
d-ary heap한 node가 d개 child를 갖는 heap. 높이는 낮아지지만 sift-down 비교 수는 늘어난다.

4. PQ ADT와 representation invariant

ADT: offer(x), peek(), poll(), size(). 선택적으로 remove(id), changePriority(id,p). empty·full·duplicate id·tie의 결과도 계약이다.

  1. RI-1 bounds: 0≤size≤capacity, live 원소는 정확히 a[0..size).
  2. RI-2 shape: prefix가 complete tree이므로 hole이 없다.
  3. RI-3 order: 모든 i>0에서 !before(a[i],a[parent(i)]).
  4. RI-4 comparator: priority와 sequence의 lexicographic order가 실행 중 바뀌지 않는다.
  5. RI-5 identity: handle map을 쓰면 모든 live id에 대해 map[a[i].id]=i, map의 모든 항목도 배열을 역참조한다.
  6. RI-6 ownership: 항목 payload lifetime과 mutation 권한이 API 계약과 일치한다.

왜 root가 최소인가? RI-3을 root→어떤 node 경로에 반복 적용하면 root≤…≤node. 경로 길이에 대한 귀납법으로 root≤모든 원소이므로 root가 전역 최소다.

5. offer와 sift-up 정당성

새 원소를 tail에 두면 shape는 보존되고, 새 node→root 경로를 제외한 edge의 order도 그대로다. 반복문의 불변식은 “위반 가능 edge는 현재 i와 parent 사이 하나뿐”이다. parent보다 앞서면 swap한다. swap 뒤 아래 edge는 고쳐지고 위반 가능성만 한 level 위로 이동한다. root 도달 또는 비교 통과로 종료하며 height가 ⌊log₂n⌋이므로 Θ(log n).

bool push(Heap *h, Item x) {
  if (h->size == h->cap) return false; // 실패 전에 검사
  size_t i = h->size;
  h->a[i] = x;
  h->size++;
  while (i > 0) {
    size_t p = (i - 1) / 2;
    if (!before(h->a[i], h->a[p])) break;
    swap_and_fix_map(h, i, p);
    i = p;
  }
  return true;
}

6. poll과 sift-down: 더 작은 child를 골라야 한다

root를 저장하고 last를 root로 옮긴 뒤 size를 줄인다. 두 child subtree는 이미 heap이다. 현재 node가 두 child 중 더 앞선 child와 순서가 맞으면 양쪽 모두와 맞고 종료한다. 아니면 그 child와 swap해 위쪽 RI를 복구하고 위반 가능성을 아래 한 경로로 이동한다.

최소 반례: root=9, left=2, right=1에서 임의로 left 2와 swap하면 root=2지만 right=1이 더 작아 RI가 깨진다. 반드시 두 child 중 comparator상 앞선 쪽을 고른다.

while (i < size / 2) { // child가 있는 node만: 2*i+1 overflow 방지
  size_t c = 2*i + 1, r = c + 1;
  if (r < size && before(a[r], a[c])) c = r;
  if (!before(a[c], a[i])) break;
  swap_and_fix_map(i, c);
  i = c;
}

7. bottom-up heapify가 Θ(n)인 이유

반복 push는 각 항목에 O(log n)을 주어 O(n log n) 상한이다. 그러나 bottom-up은 leaf를 건너뛰고 index ⌊n/2⌋−1부터 sift-down한다. 높이 h인 node 수는 대략 n/2^(h+1)이므로 전체 일은 Σ h·n/2^(h+1) < n의 수렴하는 급수, 즉 Θ(n)이다. “각 node가 log n”이라는 느슨한 상한은 실제 높이 분포를 잃는다.

10. Memory/locality와 표현 trade-off

  • 연속 배열: pointer tree보다 node overhead·allocation·cache miss가 작다. 단, growth 때 peak memory와 element move가 생긴다.
  • payload 간접화: 큰 object 전체를 swap하지 말고 작은 handle/index를 heap에 두면 write traffic이 줄지만 indirection이 늘어난다.
  • d-ary: height log_d n은 낮지만 pop마다 d child를 비교한다. decrease-key가 많은 graph workload와 cache line 크기로 실측한다.
  • index map: 취소는 빨라지나 모든 swap이 map write를 동반하고 두 구조의 원자적 RI가 필요하다.
  • dynamic capacity: geometric growth는 append allocation을 amortize하지만 실시간 tail SLA에는 reserve/bounded arena가 더 예측 가능할 수 있다.

12. 언어 library를 읽을 때 확인할 계약

  • Python heapq: list 자체를 min-heap으로 쓰며 heapify는 linear time. task priority 변경/삭제 recipe는 entry finder와 removed marker를 사용한다.
  • Java PriorityQueue: head는 least element, tie는 임의이며 iterator는 정렬 순서를 보장하지 않는다. offer/poll O(log n), contains/remove(Object) O(n), thread-safe가 아니다.
  • Rust BinaryHeap: 기본 max-heap. Reverse로 min-heap을 만들 수 있고, heap 안에서 ordering이 바뀌면 논리 오류다.

언어 이름만 암기하지 말고 min/max 방향, tie, iteration order, arbitrary remove, mutation, concurrency, allocation failure 계약을 확인한다.

13. 실무 Best Practice

  1. PQ ADT와 binary heap 구현을 구분하고 workload 연산 빈도로 선택한다.
  2. comparator를 (priority, sequence)처럼 total order로 만들고 key를 immutable하게 둔다.
  3. bulk 입력은 reserve 후 bottom-up heapify하며 peak memory까지 측정한다.
  4. 취소가 드물면 lazy deletion, 많고 memory가 빡빡하면 id→index map을 비교한다.
  5. debug에서 bounds·heap-order·map 역참조를 매 연산 검사하고 production에서는 sampling한다.
  6. size, oldest lateness, offer rejection, stale ratio, sift steps, lock hold p99를 관측한다.
  7. 검증된 library를 우선하고 concurrency가 필요하면 synchronized wrapper/전용 concurrent queue를 쓴다.

15. 대기업 면접 질문 3개와 답변 포인트

Q1. Heap은 정렬되지 않았는데 왜 root가 최소인가요?
모든 parent≤child라는 edge RI를 임의 node까지의 경로에 반복 적용한다. 귀납적으로 root≤모든 node이므로 전역 최소다. sibling 사이에는 순서가 없다고 덧붙인다.
Q2. build-heap이 왜 O(n)이지 O(n log n)이 아닌가요?
높이 h인 node가 약 n/2^(h+1)개이고 비용 O(h)이므로 Σh·n/2^(h+1)=O(n). 대부분의 node가 leaf 근처라 거의 움직이지 않는다는 직관과 Θ(n) 하한도 말한다.
Q3. 취소 가능한 scheduler PQ를 어떻게 설계하나요?
id→index map으로 O(log n) remove하며 swap마다 양방향 RI를 고치거나, versioned lazy deletion 후 pop 시 stale을 버린다. cancellation 비율·memory·failure atomicity·lock·tie·clock 정책으로 선택하고 stale rebuild metric까지 답한다.
