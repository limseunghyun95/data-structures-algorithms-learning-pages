Rotation proof → AVL height RI → Red-Black black-height → repair pipeline → production cost · 140분

한 줄 요약
AVL과 Red-Black Tree는 BST ordering을 rotation으로 보존하면서 서로 다른 balance invariant를 복구해 h=O(log n)을 강제하며, correctness는 ordering 보존과 metadata·balance 복구를 나눠 증명해야 한다.

1. 초보자를 위한 용어 사전

Rotation몇 node의 parent/child 관계를 바꾸되 inorder key 순서를 그대로 두는 국소 변환.

Augmentationsubtree size·max endpoint 같은 파생값을 node에 저장하는 것. rotation마다 다시 계산해야 한다.

Mental model: rotation은 “정렬 순서 보존 장치”이고 AVL height나 RB color는 “높이 보증 장치”다. pointer만 맞았다고 balance가 맞는 것도, 색만 맞았다고 BST ordering이 맞는 것도 아니다.

순서 증명: BST RI에서 A < x < B < y < C. 회전 전 inorder도 A,x,B,y,C, 회전 후도 같다. 따라서 ordering은 보존된다. 그러나 root/parent link, x·y의 height, subtree augmentation은 별도로 갱신해야 한다.

최소 반례: x를 y.left로 바꾸기 전에 B를 x.right에 보존하지 않으면 B subtree를 잃는다. parent의 child가 여전히 x를 가리키면 두 root가 생기거나 새 y가 tree에서 orphan이 된다.

5. Ordered Map ADT와 계층화된 representation invariant

AVL과 RB는 같은 Ordered Map ADT를 구현한다. client는 get/put/remove/lowerBound/range 결과로 둘을 구분할 수 없어야 한다.

  1. 공통 RI-1 구조: single root, one parent, acyclic, reachable count=size.
  2. 공통 RI-2 순서: left의 모든 key<node<right의 모든 key, comparator 안정.
  3. 공통 RI-3 연결: child↔parent 대칭, header root와 root.parent 일치.
  4. AVL RI-4: stored height=1+max(hL,hR), empty height −1.
  5. AVL RI-5: 모든 node에서 |hL−hR|≤1.
  6. RB RI-4: root와 모든 NIL leaf는 black.
  7. RB RI-5: red node의 child는 모두 black, 즉 red-red edge 없음.
  8. RB RI-6: 한 node에서 descendant NIL까지 모든 path의 black-height 동일.
  9. 공통 RI-7 augmentation: subtree size/max 등은 child 값의 정의식과 일치.

디버깅 순서: 구조→ordering→metadata→balance를 따로 검사하면 “틀린 pointer 때문에 height도 틀린 것”과 “pointer는 맞고 height만 stale”을 구분할 수 있다.

6. AVL: 높이 차 ±1이 logarithmic height를 만드는 이유

높이 h인 AVL의 최소 node 수를 N(h)라 하자. 가장 적은 node로 높이 h를 만들려면 child 높이가 h−1과 h−2여야 하므로 N(h)=1+N(h−1)+N(h−2). Fibonacci처럼 지수적으로 증가하므로 역으로 h=O(log n), 더 정확히 최대 높이는 약 1.44 log₂n 수준이다.

case판정복구
LLz left-heavy, left child left-heavy/0Right-Rotate(z)
RRz right-heavy, right child right-heavy/0Left-Rotate(z)
LRz left-heavy, left child right-heavyLeft(child), Right(z)
RLz right-heavy, right child left-heavyRight(child), Left(z)

표준 AVL insert는 첫 unbalanced ancestor에서 single 또는 double rotation 후 그 subtree 높이가 삽입 전 수준으로 돌아가므로 구조 회전은 거기서 끝낼 수 있다. delete는 subtree 높이 감소가 위로 전파되어 여러 ancestor를 연속 복구할 수 있다.

7. Red-Black: 느슨한 balance를 색으로 인코딩한다

black-height가 b이면 subtree에는 적어도 2^b−1 internal node가 있다. red-red가 금지되어 어떤 root→NIL path도 black node 사이에 red를 하나보다 많이 끼울 수 없으므로 전체 높이는 black path의 2배 이하. 따라서 h≤2log₂(n+1)이다.

insert 상황의미mental action
새 leaf를 red로black-height는 즉시 보존red-red만 검사

RB delete의 “double black”은 실제 세 번째 색이라기보다 한 path의 black count가 하나 부족하다는 회계 표기다. sibling 색과 nephew 색에 따라 recolor·rotation하며 deficit을 없애거나 parent로 올린다. case가 많아 손 구현 오류가 특히 잦다.

8. Rotation 정당성과 metadata 갱신 순서

구조 proof obligation: subtree의 외부 key interval, inorder sequence, 모든 내부 node의 유일 parent, 외부 parent가 가리키는 subtree root를 보존한다.

metadata proof obligation: left rotation 뒤 먼저 아래로 내려간 x를 pull(x)하고, 그 결과를 읽어 새 root y를 pull(y)한다. 반대로 하면 y가 x의 stale height/size를 읽는다.

Node *rotate_left(Tree *t, Node *x) {
  Node *y = require(x->right);
  Node *b = y->left;

  replace_child_or_root(t, x->parent, x, y);
  y->left = x;  x->parent = y;
  x->right = b; if (b) b->parent = x;

  pull(x);  // 아래 node 먼저: height/size/max...
  pull(y);  // 새 subtree root 다음
  return y;
}

augmentation이 여러 개면 각각 같은 dependency 순서를 지켜야 한다. Linux의 augmented rbtree API도 propagation/copy/rotation callback을 분리해 회전 시 이전 root 값을 복사·재계산하도록 한다.

Linux 문서는 RB가 AVL보다 lookup은 약간 느릴 수 있지만 insert/delete의 rotation 수를 실시간 worst-case로 제한하기 좋다고 설명한다. 그러나 실제 선택은 구현 품질, key 비교 비용, cache, concurrency가 이론적 차이보다 클 수 있다.

11. 실측: 정렬 100만 key를 height 19로 막는 비용

Apple clang 21.0.0, C11 -O3 -Wall -Wextra -Werror, 100만 unique key와 100만 random hit query. 5회 실행의 중앙값이며 arena-index AVL이다.

plain BST에 정렬 입력을 넣으면 height 999,999, 누적 insert comparison은 499,999,500,000이다. AVL은 거의 key마다 rotate해도 전체 build를 O(n log n) 안에 묶었다.

중요한 역전: 정렬 입력 AVL이 더 낮고 비교도 적지만 lookup wall-clock은 더 느렸다. rotation 뒤 logical shape와 arena allocation order가 어긋나 생긴 locality 차이다. comparison count와 cache miss를 함께 측정해야 한다.

검증: LL/RR/LR/RL 네 case, 20만 random put differential test, full-capacity exact-state failure atomicity, global ordering·stored height·balance factor를 검사했고 ASan/UBSan을 통과했다.

14. 테스트 전략

  • 회전 golden: 30-20-10, 10-20-30, 30-10-20, 10-30-20이 모두 root 20의 같은 inorder tree가 된다.
  • 구조 RI: cycle/shared/orphan, parent symmetry, root parent, reachable count.
  • AVL RI: 각 node의 recomputed height와 stored height 일치, factor 범위.
  • RB RI: root/NIL black, red-red 없음, 모든 NIL path black-height 동일.
  • Differential: random put/get/remove/range를 표준 ordered map과 비교한다.
  • Adversarial: sorted/reverse/alternating min-max/all-equal과 delete cascade.
  • Failure injection: allocation·key copy 실패 전후 root/size/inorder/metadata가 동일한지 확인한다.
  • Rotation instrumentation: 네 case, recolor, fix-up step, max height를 workload별 집계한다.
  • Sanitizer/concurrency: ASan/UBSan/TSan과 iterator·lock protocol을 별도 검증한다.

15. 실무 Best Practice

  1. 검증된 library 우선: RB delete를 면접용으로 이해하되 production에서 새로 쓰지 않는다.
  2. RI를 계층별 assert: debug build에서 ordering, parent, height/color, augmentation을 분리한다.
  3. Repair path는 allocation-free: local commit 뒤 rotation/recolor가 실패하지 않게 한다.
  4. Workload로 AVL/RB 선택: read/update 비율과 p99, 회전·cache miss를 실제 key로 측정한다.
  5. Comparator/key immutability: Day 23 계약을 balance 구현에도 동일하게 적용한다.
  6. Augmentation callback 단일화: 모든 rotation/delete가 같은 pull logic을 거치게 한다.
  7. Concurrency는 별도 설계: balanced tree라는 사실은 thread safety를 제공하지 않는다.
  8. 관측: size뿐 아니라 height, rotations/update, recolors, comparisons, cache miss, lock hold p99를 낸다.

17. 대기업 면접 질문 3개와 답변 포인트

Q1. Rotation이 BST ordering을 보존한다는 것을 증명하세요.
left rotation에서 subtrees A,B,C에 대해 A<x<B<y<C를 놓는다. 전후 inorder가 A,x,B,y,C로 동일함을 보이고, B parent·외부 parent/root·metadata 갱신까지 구현 책임을 말한다.
Q2. AVL과 Red-Black을 비교하고 언제 고르겠습니까?
AVL factor≤1과 약 1.44log n, RB red-red/equal black-height와 ≤2log(n+1)를 설명한다. lookup-heavy는 AVL 가능, mixed update와 검증된 표준 구현은 RB가 흔하지만 실제 p99·cache·library를 측정한다고 답한다.
Q3. Red-Black invariant가 왜 logarithmic height를 보장하나요?
black-height b subtree에 최소 2^b−1 node가 있고, red-red 금지로 어떤 path도 black node 수의 2배보다 길 수 없다. 따라서 h≤2b≤2log₂(n+1). root/NIL black convention을 먼저 선언한다.
