한 줄 요약
Heapsort는 비교만으로 worst Θ(n log n)·O(1) 보조 공간을 보장하고, counting/radix sort는 정수 key의 범위·digit 표현을 이용해 비교 정렬의 Ω(n log n) 하한을 우회한다. 대신 stability, key-range 검증, 추가 메모리, cache와 signed-key 변환이 새로운 정확성 계약이 된다.

2. 문제·입출력·제약 mental model

4. Sorting ADT와 representation invariant

공통 ADT: sort(A,key)의 사후조건은 ① 모든 i<j에서 key(A[i])≤key(A[j]), ② 출력 identity multiset=입력 identity multiset이다. stable 계약이라면 ③ 같은 key의 입력 순서도 보존한다.

Heapsort RI: active heap은 A[0:h), sorted suffix는 A[h:n)다.

0-based: parent(i)=(i-1)//2, left=2i+1, right=2i+2 heap: 모든 0<i<h 에 대해 A[parent(i)].key ≥ A[i].key suffix: A[h:n)은 nondecreasing이며, 그 모든 key ≥ A[0:h)의 모든 key

Counting RI: histogram 뒤 count[v]는 key v의 빈도, prefix sum 뒤에는 key≤v의 개수다. 안정 배치 중 count[v]는 아직 채우지 않은 v 구간의 다음 오른쪽 경계를 가리킨다.

LSD radix RI: t번 pass가 끝나면 배열은 하위 t개 digit을 key로 보았을 때 stable하게 정렬되어 있다. 다음 pass가 stable이어야 이전 digit 순서가 보존된다.

5. Heapsort: build-heap은 왜 Θ(n)인가

각 원소를 하나씩 insert하면 O(n log n)이지만, bottom-up heapify는 leaf를 건드리지 않고 마지막 내부 노드부터 sift-down한다. 높이 h인 노드는 최대 n/2h+1개이고 비용은 O(h)이므로 전체는 다음 수렴급수로 Θ(n)이다.

Σ(h≥0) (n / 2^(h+1)) · O(h) = O(n) Build: for i=floor(n/2)-1 ... 0: siftDown(i,n) Sortdown: swap(A[0],A[h-1]); h--; siftDown(0,h)

sortdown은 n−1번 각각 O(log n)이므로 Θ(n log n). 전체 worst/average/best 모두 Θ(n log n), iterative 구현의 auxiliary space는 O(1)이다. 일반 heapsort는 unstable하다.

6. Heapsort 정당성

  1. Build: i의 두 자식 subtree는 이미 heap이다. sift-down이 i를 알맞은 경로로 내리면 i subtree도 heap이 된다. 역순 귀납으로 root 전체가 heap이다.
  2. Maximum: parent≥child를 root까지 따라가면 A[0]은 active heap의 최댓값이다.
  3. Extraction: root를 A[h−1]과 바꾸면 active maximum이 suffix 맨 앞에 놓인다. h를 줄이고 root만 sift-down하면 heap RI가 복구된다.
  4. Termination: h가 매번 1 감소한다. h=1이면 suffix와 남은 한 원소를 합친 전체 배열이 정렬되고 permutation은 swap만 했으므로 보존된다.
최소 불안정 반례: [(2,a),(2,b),(1,x)]를 max-heap sort하면 root extraction 과정에서 두 2의 상대 순서가 바뀔 수 있다. heap property는 key 관계만 보장하며 identity 순서는 표현 불변식에 없다.

7. Counting sort: 위치를 “비교”하지 않고 “센다”

def counting_sort(a, range_cap): lo, hi = min(key(x) for x in a), max(key(x) for x in a) k = checked_add(checked_sub(hi, lo), 1) if k > range_cap: raise RangeTooWide count = [0] * k for x in a: count[key(x) - lo] += 1 for i in range(1, k): count[i] += count[i-1] out = [None] * len(a) for x in reversed(a): # stable의 핵심 i = key(x) - lo count[i] -= 1 out[count[i]] = x return out

음수 key는 key−lo offset으로 0-based slot에 옮긴다. cumulative count가 key별 출력 구간의 오른쪽 경계이고, 입력을 오른쪽부터 읽어 뒤쪽 동일 key부터 뒤쪽 slot에 놓으므로 상대 순서가 유지된다.

복잡도: time Θ(n+k), stable output형 space Θ(n+k). k가 n과 같은 정도로 작을 때만 실질적 선형이다. [0, 2³¹−1] 두 원소는 n=2지만 k≈21억이라 그대로 allocation하면 장애가 된다.

8. LSD radix: stability를 귀납 가정으로 쓴다

32-bit signed integer, base b=256 biased = uint32(key) XOR 0x80000000 for shift in [0, 8, 16, 24]: stable_counting_pass((biased >> shift) & 0xFF)
  1. Base: 첫 stable pass 뒤 8 low bits 순서로 정렬된다.
  2. Induction: 하위 t자리 순서가 맞다고 가정한다. t+1번째 자리로 stable 정렬하면 그 자리 값이 작은 그룹이 먼저 오고, 같은 그룹 안의 하위 t자리 순서는 유지된다.
  3. Conclusion: d개 자리 뒤 전체 key 순서가 맞다.

time Θ(d(n+b)), extra space Θ(n+b). base를 키우면 pass d는 줄지만 count table이 cache를 더 차지한다. signed two's-complement는 단순 unsigned 순서와 다르므로 최상위 sign bit를 flip해 순서를 bias한다. 문자열은 길이·종료 문자의 정렬 의미를 먼저 정의해야 한다.

9. 비교 정렬 Ω(n log n)과 “우회”의 정확한 의미

서로 다른 n개 원소의 가능한 순열은 n!개다. 비교 한 번은 decision tree를 최대 두 갈래로 나누므로 높이는 최소 log₂(n!)=Ω(n log n)이다. Heapsort는 이 하한에 맞는다.

Counting/radix가 모순이 아닌 이유는 비교 결과만 보지 않고 key의 숫자 값·digit을 직접 주소 계산에 사용하기 때문이다. 계산 모델이 강해졌고 비용도 k, d, b, word width를 포함한다. “모든 정렬을 O(n)에 한다”가 아니다.

11. 테스트 전략

  1. 공통 oracle: sortedness, identity permutation, reference sort 일치를 각각 검사한다.
  2. Exhaustive: heap은 n=0..8 모든 permutation을 대조하고 heap RI를 build/extract마다 assert한다.
  3. Stability: (key, originalIndex)로 counting/radix의 동률 index가 증가하는지 검사한다.
  4. Boundary: empty, one, all equal, negative, INT_MIN/MAX, k=cap과 cap+1, overflow 직전.
  5. Radix differential: signed/unsigned 변환, 각 pass 후 하위 digit RI, 다양한 base를 reference와 비교한다.
  6. Fault injection: allocation 실패, key extractor 예외, cancellation에서 원본 mutation·scratch 회수 계약을 검사한다.
오늘 검증: Python 3.11.6에서 heapsort n≤8 전 순열, counting/radix duplicate stability, sortedness·identity permutation을 통과했다. k cap 초과 입력은 allocation 전에 ValueError로 거부됨을 확인했다.

13. Memory와 locality

  • Heap은 배열이 연속이어도 parent→child index가 지수적으로 벌어져 sortdown 후반의 cache locality와 branch prediction이 불리하다.
  • Counting은 count table이 L1/L2에 들어가면 좋지만 k가 커지면 zero-fill·page fault·cache/TLB miss가 n보다 지배적일 수 있다.
  • Radix는 sequential scan이라 prefetch에 유리하지만 매 pass 입력과 출력 n개를 왕복한다. 큰 record 대신 index/pointer를 정렬하면 bytes moved를 줄일 수 있다.
  • Scratch buffer를 요청마다 새로 할당하지 말고 size cap이 있는 pool/thread-local reuse를 검토하되, 거대한 buffer retention과 민감 데이터 잔존을 관리한다.

15. 실무 best practice와 anti-pattern

Best practice

  • 검증된 표준 library sort를 기본값으로 두고, 실제 profile이 병목을 보일 때 specialized path를 추가한다.
  • counting 전 min/max를 한 번 scan하고 checked k, 최대 bytes, k/n ratio를 모두 검사한다. 정책 결과를 metric으로 남긴다.
  • radix는 bit width·signedness·endianness와 stability를 API/테스트에 고정하고 base는 cache와 pass 수를 benchmark해 정한다.
  • quicksort 계열의 depth/bad-partition budget이 소진될 때 heapsort를 fallback으로 써 worst latency를 봉쇄한다.
  • 큰 record는 key+index를 정렬하고 최종 permutation을 적용하며, scratch 재사용에는 상한을 둔다.
  • OpenJDK처럼 type·size·run 패턴별로 heap/counting/insertion/merge 경로를 고르는 hybrid는 threshold를 workload와 하드웨어에 맞게 재검증한다.

Anti-pattern

  • O(n)만 홍보: counting의 k, radix의 d·b와 memory traffic을 숨긴다.
  • range 검증 뒤 또 scan하지 않음: concurrent mutation이나 TOCTOU로 key가 범위를 벗어난다.
  • in-place counting을 무조건 선택: record stability와 identity 보존을 쉽게 깨뜨린다.
  • radix pass를 불안정하게 구현: 마지막 digit만 정렬된 듯 보이는 조용한 데이터 오류가 난다.
  • heapsort가 O(1)이니 항상 빠르다: 비교 수·swap·cache locality와 큰 record 이동을 무시한다.

16. 대기업 면접 질문 3개와 답변 포인트

Q1. Bottom-up build-heap이 왜 O(n log n)이 아니라 Θ(n)인가요?
대부분의 노드는 leaf 근처라 내려갈 높이가 작다. 높이 h 노드는 최대 n/2h+1개이므로 비용 합 Σ n·h/2h+1가 O(n)으로 수렴하고, 배열을 읽어야 하므로 Ω(n)이다.
Q2. Counting sort가 Ω(n log n) 하한을 어떻게 깨나요?
그 하한은 comparison decision tree 모델에만 적용된다. Counting은 정수 값을 직접 index로 사용해 더 강한 연산을 허용하고 Θ(n+k) 시간·Θ(n+k) 공간을 지불한다. k가 크면 더 나쁘거나 실행 불가능하다.
Q3. LSD radix에서 stable pass가 왜 필수이며 signed int는 어떻게 처리하나요?
상위 digit이 같은 그룹에서 이전 하위 digit 순서를 보존해야 귀납이 성립한다. 32-bit two's-complement는 uint32로 본 뒤 sign bit를 XOR해 음수 구간이 양수보다 앞서도록 bias하고, 8bit digit을 stable counting pass한다.
