한 줄 요약
재귀는 더 작은 같은 문제의 결과를 조합하는 설계다. 올바름은 well-founded measure와 구조적 귀납법으로, 시간은 전체 호출 트리의 일로, 공간은 동시에 살아 있는 call stack의 최대 깊이로 분석한다.

1. 초보자를 위한 용어 사전

Recursion함수가 자기 자신과 같은 명세를 더 작은 입력에 적용해 답을 만드는 방식.
Base case추가 재귀 호출 없이 직접 답하는 가장 작은 입력. 종료의 닻이다.
Recursive case입력을 더 작은 subproblem으로 나누고 그 반환값을 조합하는 경우.
Call stack / frame아직 끝나지 않은 호출을 LIFO(last in, first out: 마지막에 들어온 것이 먼저 나감)로 보관하는 실행 구조 / 한 호출의 parameter, local state, 돌아갈 위치를 담는 기록.

RecurrenceT(n)을 더 작은 입력의 비용으로 정의한 점화식. 코드의 호출 구조를 수학으로 옮긴다.

Well-founded measure무한히 감소할 수 없는 진행 척도. subtree node 수처럼 매 호출에서 엄격히 작아져야 종료한다.
Memoization같은 subproblem 결과를 cache해 다시 계산하지 않는 기법.
Tree / subtree / heightcycle 없이 parent-child로 연결된 구조 / 한 Node 아래의 작은 tree / 이 자료에서는 가장 긴 root-to-leaf 경로에 포함된 Node 수.
Cycle / DAGlink를 따라 출발점으로 되돌아오는 경로 / cycle은 없지만 한 child를 여러 parent가 공유할 수 있는 방향성 비순환 그래프.
ADT / RI사용자가 보는 값·연산 계약 / concrete object가 유효한 ADT 표현이기 위해 항상 지켜야 할 조건.
Θ(n)입력이 커질 때 비용이 n에 비례하는 상한과 하한을 동시에 갖는다는 타이트한 점근 경계.

3. 문제·입출력·제약 mental model

문제: 유한한 binary tree 한 개를 입력받아 (node_count, height)를 한 번의 traversal로 반환한다. 여기서는 empty height=0, leaf height=1로 정의한다.

  • 입력: None 또는 Node(value, left, right)의 root reference.
  • Precondition: root에서 도달 가능한 object가 유한하고 cycle·shared child가 없는 tree이며, 실행 중 child link가 바뀌지 않는다.
  • Postcondition: count는 도달 가능한 Node 수, height는 root-to-empty 경로 중 Node 수의 최댓값이다.
  • 크기 변수: n=node 수, h=tree height. 같은 n이라도 balanced tree는 h=Θ(log n), chain은 h=Θ(n)이다.
  • 운영 제약: 입력 출처, 가능한 최대 깊이, cycle/shared semantics, latency·memory budget을 먼저 정한다.

4. ADT·표현·representation invariant

BinaryTree ADT는 Empty 또는 Node(value, leftTree, rightTree)라는 recursive value다. abstraction function은 concrete None을 Empty로, Python Node와 child reference를 abstract Node와 두 subtree로 해석한다.

  • RI-1 유한성: root에서 도달 가능한 Node 수가 유한하다.
  • RI-2 acyclic: child link를 따라 자기 조상으로 돌아가지 않는다.
  • RI-3 unique parent: root 외 Node는 정확히 한 parent에서 도달한다. 같은 object를 두 child가 공유하면 일반 tree가 아니라 DAG다.
  • RI-4 query stability: 분석 중 구조가 변경되지 않는다. 생성 뒤 바뀌지 않는 immutable tree나 특정 시점의 복제본인 snapshot이 가장 단순하다.

public constructor·deserializer에서 RI를 한 번 검증하고 내부 query는 유효한 tree를 가정해야 한다. 매 query마다 전체를 검사하면 분석을 두 번 순회하고, 전혀 검사하지 않으면 untrusted cycle이 종료성 가정을 깨뜨린다.

5. 직접 구현: child 결과를 한 번에 조합

from __future__ import annotations
from dataclasses import dataclass

@dataclass(frozen=True, slots=True)
class Node:
    value: int
    left: Node | None = None
    right: Node | None = None

def analyze(root: Node | None) -> tuple[int, int]:
    """Return (node_count, height). Requires the BinaryTree RI."""
    if root is None:                 # base case
        return 0, 0

    left_n, left_h = analyze(root.left)
    right_n, right_h = analyze(root.right)
    return 1 + left_n + right_n, 1 + max(left_h, right_h)

한 frame은 root reference와 두 child 결과, 반환 위치를 보관한다. 왼쪽 호출이 반환된 뒤 오른쪽을 호출하므로 전체 n개 frame이 한꺼번에 존재하는 것이 아니라 한 root-to-leaf 경로의 Θ(h)개만 동시에 살아 있다.

6. Call stack 흐름: push와 unwind

순서활성 frame의미
1analyze(A)A의 child 결과를 기다림
2A → B왼쪽 subtree frame push
3A → B → Nonebase case가 (0,0)을 반환
4A → BB의 두 결과를 합쳐 (1,1), unwind
5A → C오른쪽 subtree를 같은 계약으로 계산
6A(1,1)+(1,1)+root → (3,2)

면접 함정: 총 호출 수(total work)와 최대 활성 호출 수(peak stack)는 다르다. branch가 두 개여도 두 child 호출은 순차 실행되므로 이 예제의 시간은 Θ(n), 보조 stack은 Θ(h)다.

7. 정당성·종료성: 구조적 귀납법

  1. 명제 P(t): analyze(t)가 t의 정확한 node 수와 정의한 height를 반환한다.
  2. Base: t=Empty면 node가 0개이고 height=0이므로 (0,0)은 정확하다.
  3. Induction hypothesis: left와 right subtree에 대해 P(left), P(right)가 참이라고 가정한다.
  4. Step: RI의 unique-parent 조건 때문에 root·left node 집합·right node 집합은 서로 겹치지 않는다. 따라서 count는 1+left_n+right_n, height는 1+max(left_h,right_h)다.
  5. Termination: measure를 subtree node 수로 두면 각 non-empty child는 parent tree보다 엄격히 작다. 자연수의 무한 감소는 없으므로 base case에 도달한다.
최소 반례: x.left = x인 한 Node cycle은 “child가 더 작다”는 measure를 깨뜨린다. base case에 도달하지 못해 stack이 계속 커진다. 코드 한 줄의 문제가 아니라 입력이 BinaryTree RI를 만족하지 않는 문제다.

8. Recurrence·시간·공간·amortized·locality

항목분석
일반 tree 시간T(n)=T(nL)+T(nR)+Θ(1), nL+nR=n−1. 각 Node를 한 번 처리하므로 Θ(n).
balanced 특수형T(n)=2T(n/2)+Θ(1)=Θ(n). Master Theorem의 leaf-dominant case.
chain 특수형T(n)=T(n−1)+Θ(1)=Θ(n). Master Theorem 형태가 아니므로 펼쳐서 합한다.
보조 공간call stack Θ(h): balanced Θ(log n), chain Θ(n). 반환 tuple 외 출력은 Θ(1).
Amortized이 read-only traversal 자체에는 상각 분석이 필요 없다. 결과 list에 append하면 dynamic array append의 amortized Θ(1)이 별도로 더해진다.
Memory/localitylinked Node는 pointer chasing과 cache miss가 생긴다. explicit stack은 call overhead를 줄일 수 있지만 Node 배치를 바꾸지 않으므로 locality를 자동 해결하지 않는다.

점화식 원칙: 함수 안에 재귀 호출이 두 줄 있다는 이유만으로 2T(n−1)이라 쓰지 않는다. 각 호출의 실제 입력 크기와 subtree가 겹치는지를 적어야 한다. disjoint tree traversal은 총 n개 Node, naive Fibonacci처럼 같은 상태를 반복하면 exponential work다.

9. 테스트: example·property·differential

def analyze_iterative(root):
    if root is None:
        return 0, 0
    count = 0
    max_depth = 0
    stack = [(root, 1)]
    while stack:
        node, depth = stack.pop()
        count += 1
        max_depth = max(max_depth, depth)
        if node.left is not None:
            stack.append((node.left, depth + 1))
        if node.right is not None:
            stack.append((node.right, depth + 1))
    return count, max_depth

cases = [
    None,
    Node(1),
    Node(1, Node(2), Node(3)),
    Node(1, Node(2, Node(3))),
]
for tree in cases:
    n, h = analyze(tree)
    assert analyze_iterative(tree) == (n, h)
    assert (n == 0) == (h == 0)
    assert n == 0 or (1 <= h <= n <= 2**h - 1)

example test는 empty·leaf·balanced·skewed 경계를, property는 binary tree가 만족해야 할 관계를, differential test는 recursive/iterative 구현의 같은 결과를 확인한다. 무작위 tree generator는 최대 depth를 강제하고 seed를 기록한다.

10. Error handling과 production Best Practice

  • 신뢰 경계 검증: deserialize할 때 값이 아니라 “같은 object인가”를 보는 identity 기반 seen set으로 cycle/shared node를 탐지한다. 잘못된 type은 TypeError, 잘못된 구조는 ValueError로 거부하거나 graph semantics를 명시한다.
  • resource budget: max_nodes, max_depth, 종료 시각인 deadline과 중단 신호인 cancellation을 API 계약에 둔다. 악성 깊이 입력은 stack exhaustion 또는 CPU denial-of-service가 된다.
  • Python 한계: 최대 interpreter stack depth를 넘으면 RecursionError가 난다. sys.setrecursionlimit()를 무작정 높이면 문서상 너무 높은 limit이 crash로 이어질 수 있으므로 입력이 깊다면 iterative로 바꾼다.
  • 실패 원자성: traversal 중 DB write·메일 전송 같은 side effect를 하지 말고 먼저 결과/command를 모은 뒤 성공 시 commit한다. 중간 RecursionError 후 재시도하면 중복 효과가 날 수 있다.
  • DAG와 memoization: 겹치는 subproblem이면 state key별 cache로 O(V+E)에 가깝게 줄인다. 단, unbounded cache는 memory leak이며 mutable/impure 함수 결과를 cache하면 stale·잘못된 결과가 된다.
  • 동시성: Python functools.cache의 내부 자료구조는 thread-safe지만 저장된 결과가 아직 없는 cache miss가 동시에 두 번 계산될 수 있다. “정확히 한 번 실행”이 필요한 side effect와 혼동하지 않는다.
  • 관측: 처리 node 수, 최대 depth, cache hit/miss, budget rejection, RecursionError를 metric으로 남긴다. 평균 n만 보면 드문 chain 입력을 놓친다.
Anti-pattern: base case만 있으면 종료한다고 믿기, 입력을 slice/copy해 매 frame Θ(n) 일을 만들기, height()를 각 Node에서 반복 호출해 Θ(n²)로 만들기, 외부 깊이를 검증하지 않고 recursion limit만 올리기, 무제한 memo cache에 request별 state를 영구 보관하기.

11. 35분 실습과 benchmark 주의점

  1. balanced tree와 left-chain을 n=31, 127, 511…로 생성해 recursive/iterative 결과를 교차 검증한다.
  2. validate_tree(root, max_nodes, max_depth)를 explicit stack+identity set으로 구현하고 cycle·shared child·budget 초과 오류를 각각 테스트한다.
  3. 별도 size()와 height()를 반복 호출하는 잘못된 balanced-check와, 한 호출이 (is_balanced,height)를 반환하는 구현을 비교한다.
  4. 재귀 depth와 wall time, peak memory를 기록하고 어느 h부터 iterative 정책으로 전환할지 근거를 문서화한다.

Benchmark: tree 생성·RI 검증은 측정 밖에 두되 실제 endpoint 전체 비용도 따로 잰다. balanced/skewed를 섞지 말고 같은 n에서 shape별로 비교한다. warm-up 후 여러 번 측정해 중앙값인 median과 99% 요청이 이 값 이하인 p99를 기록하고, recursive/iterative가 동일 결과인지 매 run 전에 확인한다. tracemalloc 수치만으로 Python interpreter 아래의 native/C stack 전체를 측정했다고 단정하지 않는다.

12. 대기업 면접 질문 3개와 답변 포인트

  1. 이진 트리 순회의 시간과 공간 복잡도를 설명하세요.
    각 Node를 한 번 방문해 시간 Θ(n), 동시에 활성인 frame은 한 경로뿐이라 stack Θ(h)라고 분리한다. balanced와 skewed의 h를 각각 Θ(log n), Θ(n)으로 말한다.
  2. 재귀 함수의 correctness와 termination을 어떻게 증명하나요?

  3. production에서 recursion을 iteration으로 바꾸는 기준은?
    입력 깊이 상한·언어 stack limit·frame overhead·cycle 가능성·side effect를 본다. 깊이가 외부 통제거나 h=Θ(n)이면 explicit stack, 겹치는 상태면 bounded memoization, graph면 visited 상태를 선택한다.
