한 줄 요약
배열 index는 base + i × element_size로 Θ(1)에 계산되지만, 실제 속도는 가져온 cache line의 나머지 값을 곧 재사용하는지에 달려 있다. 복잡도·주소 안전성·memory locality를 함께 봐야 한다.

1. 초보자를 위한 용어 사전

Array같은 크기의 element를 index 0…n-1로 접근하는 sequence ADT의 대표 표현.
Contiguouselement의 byte 구간들이 메모리 주소상 빈틈없이 연속해 있다는 뜻.

Memory hierarchyregister, L1/L2/last-level cache, DRAM처럼 작고 빠른 층부터 크고 느린 층까지 이어진 저장 계층.

False sharing서로 다른 변수를 쓰는 thread들이 우연히 같은 cache line을 공유해 coherence traffic을 만드는 현상.

3. 문제·입출력·제약 mental model

문제: signed 64-bit 정수 n개를 고정 길이로 저장하고 get(i), set(i,x), 전체 합계를 제공하는 DenseVector를 만든다. 이후 4,096×4,096 row-major matrix를 모두 합산한다.

  • 입력: n, index i, int64 값 x. matrix는 n×n이며 여기서는 128MiB다.
  • 출력: get은 한 값, set은 성공 여부, scan은 overflow 정책이 정의된 합계.
  • 오류: i<0 또는 i≥n, n×8 overflow, allocation 실패, int64 범위 밖 값.
  • workload A: row→column 순서, stride 8 bytes. 한 line에서 여러 이웃 값을 소비한다.
  • workload B: column→row 순서, stride 32,768 bytes. 같은 횟수의 값을 읽지만 먼 주소로 이동한다.
  • 선택 기준: W(n), Q(n), memory footprint, page/TLB behavior, vectorization 가능성, multi-thread write pattern.
먼저 세울 가설: 두 matrix 순회는 모두 Θ(n²) loads지만 row-major 순회는 spatial locality와 hardware prefetch를 이용한다. column-major는 가져온 line의 대부분을 즉시 쓰지 못해 실제 ns/access가 커질 가능성이 높다.

4. FixedInt64Array ADT와 representation invariant

Abstract value: 길이 n의 sequence ⟨x₀,…,xₙ₋₁⟩. get(i)의 precondition은 0≤i<n, postcondition은 xᵢ 반환이다. set(i,v)는 i 위치만 v로 바꾸고 길이와 다른 값은 보존한다.

Concrete stateRepresentation invariant
lenelement 수이며 allocation byte 수가 아니다. 생성 후 고정.
datalen=0이면 NULL 허용, len>0이면 non-NULL이고 최소 len×8 bytes의 live allocation을 단독 소유.
layout각 element는 정확히 8 bytes, i번째 byte 구간은 [base+8i, base+8(i+1)).
lifetime초기화 성공 후 한 번만 free하며, free 뒤 data=NULL,len=0으로 되돌린다.

Abstraction function: 메모리의 i번째 int64 값을 abstract sequence의 xᵢ로 읽는다. 이 배열은 capacity나 resize 연산이 없는 고정 길이 ADT다. 따라서 dynamic array의 “capacity ≥ size” RI와 geometric growth는 내일 주제다.

5. 주소 계산이 Θ(1)인 이유 — 그리고 조건

모든 element 폭이 w로 같으면 i 앞에는 정확히 i개, 총 i×w bytes가 있다. 따라서 addr(i)=base+i×w다. linked list처럼 i개의 next pointer를 따라갈 필요가 없어 산술 연산 몇 번으로 위치를 구한다.

  • 1차원 int64: addr(i)=base+8i.
  • row-major n×m: addr(r,c)=base+(r×m+c)×w.
  • jagged array: 각 행이 별도 allocation이면 위의 단일 base 공식이 그대로 성립하지 않는다.
  • Python list: CPython의 현재 구현은 PyObject* pointer vector가 연속이다. list가 가리키는 Python object payload까지 연속이라는 뜻은 아니다.
  • Python array('q'): basic numeric 값을 compact하게 저장하고 itemsize와 buffer interface를 제공하므로 payload-contiguous 예시에 더 가깝다.
최소 반례: row-major index를 r+c로 계산하면 (0,1)과 (1,0)이 같은 위치에 충돌한다. 올바른 식 r×columns+c에는 한 행의 폭이 반드시 들어간다. 또 i×w가 integer overflow한 뒤 bounds를 검사하면 이미 잘못된 작은 offset이 만들어질 수 있다.

6. 직접 구현: overflow·bounds·ownership을 계약에 포함

#include <stdbool.h>
#include <stdint.h>
#include <stddef.h>
#include <stdlib.h>

typedef struct {
    size_t len;
    int64_t *data;
} Int64Array;

bool array_init(Int64Array *out, size_t n) {
    if (out == NULL) return false;
    *out = (Int64Array){0};          // failure state 먼저
    if (n > SIZE_MAX / sizeof(int64_t)) return false;
    if (n == 0) return true;         // zero-length 정책 고정

    int64_t *candidate = calloc(n, sizeof(*candidate));
    if (candidate == NULL) return false;
    out->data = candidate;           // 완성된 상태를 commit
    out->len = n;
    return true;
}

bool array_get(const Int64Array *a, size_t i, int64_t *out) {
    if (a == NULL || out == NULL || i >= a->len) return false;
    *out = a->data[i];
    return true;
}

bool array_set(Int64Array *a, size_t i, int64_t value) {
    if (a == NULL || i >= a->len) return false;
    a->data[i] = value;
    return true;
}

void array_destroy(Int64Array *a) {
    if (a == NULL) return;
    free(a->data);
    *a = (Int64Array){0};
}

bounds를 확인한 뒤에만 a->data[i]를 평가한다. C에서 out-of-range subscript나 allocation 밖 pointer 형성은 undefined behavior가 될 수 있다. out을 zero state로 먼저 만들고 allocation 성공 뒤 commit하면 실패 시 caller가 파괴 가능한 유효 상태를 받는다.

7. 정당성: address uniqueness와 loop invariant

  1. Allocation: overflow check로 n×8이 size_t에 표현되고, 성공 시 그 byte 수를 소유한다.
  2. 범위: 0≤i<n이면 0≤8i<8n이므로 element 시작 주소가 allocation 안이다. 8-byte 구간 끝도 최대 8n이다.
  3. 유일성: i≠j이면 8i≠8j이므로 두 element 시작 주소가 다르다. fixed-width 구간도 겹치지 않는다.
  4. get: AF가 xᵢ로 정의한 동일한 memory cell을 읽으므로 postcondition을 만족한다.
  5. set: i 구간만 쓰고 다른 구간은 겹치지 않으므로 xᵢ만 value로 바뀌고 RI가 보존된다.

scan proof: 반복 k회 직전 accumulator가 x₀+…+xₖ₋₁이라는 loop invariant를 둔다. 초기 k=0에서는 0, 한 값을 더하면 k+1에 보존되고, k=n 종료 시 전체 합이다. 단, 합계 type overflow가 가능한지 별도 precondition 또는 checked/saturating/wider accumulator 정책이 필요하다.

9. 테스트: 정상값뿐 아니라 불변식 경계를 때린다

#include <assert.h>

static void test_array(void) {
    Int64Array a;
    int64_t out = 777;

    assert(array_init(&a, 3));
    assert(a.len == 3 && a.data != NULL);
    assert(array_get(&a, 0, &out) && out == 0);
    assert(array_set(&a, 2, -9));
    assert(array_get(&a, 2, &out) && out == -9);
    assert(!array_get(&a, 3, &out));       // one-past-end
    assert(!array_set(&a, SIZE_MAX, 1));      // hostile index
    assert(!array_get(NULL, 0, &out));
    assert(!array_get(&a, 0, NULL));

    array_destroy(&a);
    assert(a.len == 0 && a.data == NULL);

    assert(array_init(&a, 0));                 // empty policy
    assert(!array_get(&a, 0, &out));
    array_destroy(&a);
}

별도 fault-injection allocator로 allocation 실패를 강제하고 out={0}인지 확인한다. AddressSanitizer/UndefinedBehaviorSanitizer와 static analyzer를 켜고, random index trace를 기준 vector와 differential test한다. C API가 signed index를 받는다면 음수를 size_t로 cast하기 전에 거부한다.

10. 같은 Θ(n²), 다른 locality benchmark

uint64_t sum_row_major(const volatile uint64_t *a, size_t n) {
    uint64_t sum = 0;
    for (size_t r = 0; r < n; ++r)
        for (size_t c = 0; c < n; ++c)
            sum += a[r * n + c];       // stride 8 B
    return sum;
}

uint64_t sum_column_major(const volatile uint64_t *a, size_t n) {
    uint64_t sum = 0;
    for (size_t c = 0; c < n; ++c)
        for (size_t r = 0; r < n; ++r)
            sum += a[r * n + c];       // stride n*8 B
    return sum;
}

환경: Apple clang 21.0.0 -O3, arm64, macOS 26.5.2. n=4096, uint64 16,777,216개=128MiB, 각 함수 5회, checksum 동일, CLOCK_MONOTONIC. compiler가 load를 제거하지 않게 volatile read와 외부 sink를 사용했다.

해석: 이 환경의 best 기준 약 9.1배 차이다. algorithmic work는 같지만 memory access order가 달라졌다. row 첫 trial이 특히 느린 것은 cold cache·page state·frequency 같은 warm-up 효과도 측정에 섞임을 보여준다. 이 숫자를 다른 CPU의 상수로 일반화하지 말고, “왜 vector 전체와 환경을 남기는가”의 사례로 본다.

  • 두 loop의 checksum, read 수, data type, allocation을 동일하게 한다.
  • 순서 편향을 줄이려면 AB/BA를 교차하고 process를 새로 띄운 결과도 비교한다.
  • page fault를 포함한 cold-start와 resident-memory steady-state를 별도 질문으로 측정한다.
  • volatile은 실험용 최적화 장벽이며 production 성능 코딩 기법이 아니다. 별도 benchmark에서는 compiler vectorization도 허용해 현실 코드를 측정한다.
  • wall time 뒤 원인은 hardware counter와 profiler로 cache/TLB miss, bandwidth, instruction 수를 확인한다.

AoS vs SoA: struct {x,y,z}의 Array of Structures는 한 entity의 모든 field를 함께 쓸 때 좋다. x만 대량 scan한다면 Structure of Arrays x[]; y[]; z[]가 필요한 field를 더 조밀하게 담는다. 이름보다 실제 query projection과 update pattern으로 고른다.

12. Error handling과 production Best Practice

  • 단위를 type/API에 드러내기: length(elements), bytes, stride(bytes)를 섞지 않는다. byte count는 overflow-checked helper에서 한 번 계산한다.
  • pointer 형성 전 검증: index bounds와 multiplication/addition overflow를 먼저 검사한다. “dereference만 안 하면 된다”는 가정도 C의 pointer 규칙에서는 위험하다.
  • 실패 원자성: allocate·populate·RI 검증을 candidate에서 끝낸 뒤 active snapshot을 교체한다. 실패하면 기존 배열을 계속 제공한다.
  • ownership: owner, borrow 기간, resize 가능 여부를 문서화한다. raw pointer·memoryview가 살아 있는 동안 length-changing operation을 금지한다.
  • 직렬화: in-memory int representation을 그대로 network/file format으로 착각하지 않는다. width, signedness, endianness, alignment, version을 명시한다.
  • 순회 순서: storage의 fastest-changing dimension을 inner loop에 두고, working set이 크면 cache-sized tile/block으로 나눈다.
  • 동시 쓰기: index가 달라도 같은 cache line이면 false sharing이 생길 수 있다. partition·thread-local accumulation을 우선 검토하고 padding은 측정 후 적용한다.
  • 관측성: p50/p99 latency, throughput, allocation failure, page fault, RSS, cache/TLB miss, NUMA placement를 목표 환경에서 profile한다.
  • 최적화 순서: ADT와 correctness → production trace → profiler → layout/loop order → blocking/vectorization 순으로 검증한다.
Anti-pattern: Python list의 object까지 연속이라 단정, bounds 검사 전에 pointer 계산, n×w overflow 무시, row-major data를 column-first로 반복 scan, microbenchmark의 cache line 크기를 모든 CPU에 고정, 평균 하나만 보고 warm-up/tail 삭제, false sharing을 확인하지 않고 무조건 padding, raw memory를 portable file format으로 저장.

14. 대기업 면접 질문 3개와 답변 포인트

  1. 배열 index 접근은 왜 O(1)이며 실제 시간도 항상 같은가요?
    fixed-width와 contiguous RI 때문에 base+i×w 산술로 위치를 구해 Θ(1)이다. 하지만 cache/TLB hit, page fault, contention에 따라 상수가 달라지므로 같은 점근 복잡도가 같은 latency를 뜻하지 않는다.
  2. row-major matrix의 loop 순서가 중요한 이유는?
    column을 inner loop로 두면 unit stride로 한 cache line의 이웃 값을 소비하고 prefetch/vectorization 기회가 생긴다. 반대 순서는 큰 stride와 낮은 line utilization을 만들어 W는 같아도 Q가 커질 수 있다.
  3. production 배열 API에서 어떤 실패를 막겠나요?
    element/byte 단위, signed index, n×w overflow, allocation null, bounds, ownership/lifetime, accumulator overflow를 계약화한다. candidate build 후 atomic swap, sanitizer/fuzz/property test, target profiler와 rollback을 포함한다.

내일 연결: Day 09에서는 fixed array를 넘어 dynamic array가 size와 capacity를 왜 분리하는지, geometric growth가 어떻게 append의 amortized Θ(1)을 만들며 resize spike·allocation failure·iterator invalidation을 어떻게 다뤄야 하는지 증명한다.
