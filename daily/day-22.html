5. Tree ADT와 representation invariant

Rooted ordered Tree ADT: root(), parent(v), 순서 있는 children(v), isLeaf(v), subtree traversal을 제공한다. 저장 주소·index·pointer는 외부 계약이 아니다.

  1. RI-1 root: empty가 아니면 root는 정확히 하나이고 parent가 없다.
  2. RI-2 one parent: 모든 non-root reachable node는 parent가 정확히 하나다.
  3. RI-3 acyclic: 어떤 node도 자기 ancestor가 될 수 없다.
  4. RI-4 reachability: 소유한 모든 node는 root에서 child edge로 정확히 한 번 도달한다. orphan이 없다.
  5. RI-5 bidirectional consistency: parent pointer를 저장한다면 c∈children(p) ⇔ parent(c)=p.
  6. RI-6 order: ordered tree이면 children의 순서는 안정적이고 traversal 의미에 포함된다.
  7. RI-7 ownership: node/value의 수명과 삭제 책임이 하나로 정의되어 dangling·double free가 없다.
  8. RI-8 cached metadata: subtree size/height를 저장한다면 구조 변경 뒤 정의식과 일치한다.

n>0인 tree는 edge가 정확히 n−1개다. root는 indegree 0, 나머지는 indegree 1이므로 합이 n−1이다. 반대로 n개 node가 모두 연결되고 cycle이 없으며 edge가 n−1이면 tree다.

7. Traversal 정당성: structural induction

Preorder 명제 P(T): 알고리즘은 T의 모든 node를 정확히 한 번 방문하고 root, 왼쪽 subtree, 오른쪽 subtree 순서를 낸다.

  1. Base: empty tree는 아무 node도 방문하지 않아 명제가 성립한다.
  2. Induction hypothesis: left/right subtree에서 각각 모든 node를 정확히 한 번 원하는 순서로 방문한다고 가정한다.
  3. Step: root를 한 번 방문한 뒤 left, right 알고리즘을 실행한다. RI의 one-parent·acyclic으로 세 node 집합은 서로 겹치지 않고 합집합이 T 전체이므로 정확히 한 번이다.

Inorder는 root 방문을 두 subtree 사이로, postorder는 뒤로 옮기면 같은 증명을 쓴다. 중요: one-parent 불변식이 없으면 left/right subtrees가 같은 node를 공유해 “정확히 한 번” 증명이 깨진다.

BFS loop invariant: 매 반복 시작에 queue에는 발견됐지만 미처리인 node만 있고, dequeue 순서는 nondecreasing depth다. depth d node를 처리하며 depth d+1 children을 뒤에 enqueue하므로 기존 d 또는 d+1 뒤에 놓여 순서가 유지된다. tree의 유일 parent로 child는 한 번만 발견된다.

8. 직접 구현: 하나의 event stack으로 pre/in/post

typedef enum { ENTER, BETWEEN, EXIT } Phase;
typedef struct { NodeId id; Phase phase; } Event;

Status traverse_binary(Tree *t, NodeId root, Visitor *v, Budget b) {
  Vec<Event> stack = try_reserve(3 * min(t->size, b.max_nodes));
  if (!stack.ok) return OOM;
  stack.push({root, ENTER});

  while (!stack.empty()) {
    if (v->cancelled()) return CANCELLED;
    Event e = stack.pop();
    if (e.id == NONE) continue;
    if (++b.events > 3 * b.max_nodes) return LIMIT_EXCEEDED;

    Node *x = checked_node(t, e.id);       // bounds/lifetime 확인
    if (!x) return INVALID_CHILD;
    if (e.phase == ENTER) {
      TRY(v->pre(x));
      stack.push({e.id, BETWEEN});
      stack.push({x->left, ENTER});
    } else if (e.phase == BETWEEN) {
      TRY(v->in(x));
      stack.push({e.id, EXIT});
      stack.push({x->right, ENTER});
    } else {
      TRY(v->post(x));
    }
  }
  return OK;
}

재귀 call frame의 “왼쪽 전/후, 오른쪽 후” 상태를 명시적 event로 옮겼다. iterator를 pause/resume하거나 cancellation·budget·typed error를 지원하기 쉽다. production에서는 3*n을 곱하기 전에 overflow를 검사하고 필요한 stack peak만 동적으로 확장한다.

9. Complexity: 시간은 같아도 공간은 모양을 따른다

순회시간aux 공간지배하는 모양
Recursive DFSΘ(n)Θ(h) call stackskewed depth
Iterative DFSΘ(n)Θ(h) explicit stackpending siblings/depth
Level-order BFSΘ(n)Θ(w)maximum level width
Morris inorderΘ(n) amortizedO(1)temporary pointer threading

완전 이진 tree는 h=Θ(log n)이지만 마지막 level의 w=Θ(n)이다. 반대로 chain은 h=Θ(n), w=1이다. 따라서 “BFS와 DFS 모두 O(n)”만 말하면 memory failure를 예측할 수 없다.

Morris 주의: predecessor의 null right pointer를 임시 thread로 바꾸고 복구한다. concurrent reader, immutable/persistent tree, callback 예외·취소가 있는 production에서는 원상 복구 보장이 어려워 O(1) 공간만 보고 선택하면 안 된다.

11. 실측: O(n) 내부의 4.31배와 queue 100만 개

Apple clang 21.0.0, C11 -O3 -Wall -Wextra -Werror, 5회 실행 중앙값. 2,097,151-node perfect binary tree를 동일한 BFS로 읽되 physical node 배치만 바꿨다.

추가 검증: 4,095-node tree에서 recursive/iterative preorder·inorder·postorder sequence가 정확히 같았다. duplicate child로 만든 multi-parent와 leaf→root cycle은 validator가 거부했고 전체 suite는 ASan/UBSan을 통과했다.

benchmark 주의: cold/warm cache, allocator, node size, traversal order, callback work를 기록한다. callback이 I/O를 하면 4배 locality 차이는 가려질 수 있다. queue allocation/build 시간을 포함한 end-to-end와 순수 visit loop를 분리한다.

13. 실무 Best Practice

  1. Validate at boundary: untrusted nested input은 구조를 business object로 공개하기 전에 node/depth/edge/ownership을 검증한다.
  2. Name the convention: height edge/node 기준, child ordering, duplicate ID, empty tree를 API 문서에 고정한다.
  3. Choose traversal by dependency: parent-before-child는 pre, child-before-parent는 post, nearest-depth는 BFS다. 익숙해서 DFS를 쓰지 않는다.
  4. Bound the frontier: DFS h와 BFS w를 입력 SLA에 포함하고 metric으로 max depth/frontier를 낸다.
  5. Separate traversal from effects: visitor는 순회와 업무 동작을 분리하되 callback 실패·취소·mutation 계약을 명시한다.
  6. Prefer arena for batch trees: AST·query plan처럼 함께 생성/해제되는 구조는 index/arena로 locality와 lifetime을 단순화한다.
  7. Delete postorder: owning pointer tree는 children을 먼저 해제한 뒤 parent를 해제해 use-after-free를 피한다.

14. 테스트 전략

  • 최소 모양: empty, one node, only-left, only-right, perfect, wide star, deep chain.
  • Golden order: 작은 labeled tree의 pre/in/post/level sequence를 손으로 고정한다.
  • Differential: safe depth의 random tree에서 recursive와 iterative 결과를 비교한다.
  • Property: output length n, ID set 동일, duplicate 없음, parent-child order property를 검사한다.
  • Malformed: out-of-range child, self-loop, ancestor cycle, duplicate parent, orphan, duplicate sibling edge.
  • Failure: stack/queue N번째 allocation 실패, visitor N번째 error, cancel, counter boundary.
  • Sanitizer: 구조 삭제·error cleanup을 ASan/UBSan/LeakSanitizer로 확인한다.

16. 대기업 면접 질문 3개와 답변 포인트

Q1. DFS와 BFS의 시간·공간 복잡도를 tree 모양까지 포함해 설명하세요.
둘 다 각 node/edge를 한 번 보므로 Θ(n). DFS는 call/explicit stack Θ(h), BFS는 queue Θ(w). perfect tree에서 h=Θ(log n), w=Θ(n), chain에서 h=Θ(n), w=1 반례와 recursion overflow·queue OOM 정책을 함께 말한다.
Q2. preorder/inorder/postorder를 언제 쓰며 inorder는 항상 정렬인가요?
root 방문 시점으로 정의하고 pre=serialize/propagate, post=aggregate/free, inorder=binary tree의 left-node-right다. sorted는 BST ordering invariant가 추가될 때만 성립하며 일반 binary tree에는 보장되지 않는다.
Q3. 외부 입력이 tree인지 어떻게 검증하나요?
root 하나, non-root indegree 1, child bounds, acyclic color DFS, root reachability, edge n−1을 제시한다. node/depth/fan-out budget과 iterative 검증, commit 전 실패 atomicity, cycle/multi-parent 최소 반례까지 설명한다.
