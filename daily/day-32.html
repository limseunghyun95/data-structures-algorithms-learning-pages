한 줄 요약
Compaction은 여러 immutable sorted run을 새 run으로 병합해 중복 version과 안전한 tombstone을 제거하는 background transaction이며, leveled와 tiered 정책은 write·read·space amplification 중 무엇을 더 지불할지 결정한다.

1. 초보자를 위한 용어 사전

Compaction여러 정렬 파일을 읽어 key 순서로 병합하고 새 SSTable을 만든 뒤 옛 파일을 교체하는 작업.
Sorted runkey 순으로 정렬된 하나의 논리 스트림. 여러 SST 파일로 range-partition될 수 있다.
Level크기 목표와 overlap 규칙을 가진 LSM의 층. L0은 보통 파일 간 key range가 겹칠 수 있다.
Leveled각 non-L0 level을 대체로 하나의 non-overlapping run으로 유지하는 정책. read/space 비용을 줄이는 대신 rewrite가 많다.
Tiered / Universal비슷한 크기의 여러 run을 모아 더 큰 run으로 합치는 정책. write는 줄지만 read·임시 공간이 늘 수 있다.
Fanout T인접 level의 목표 크기 비율. 예: T=10이면 다음 level이 약 10배 크다.
Overlap두 파일의 key range가 교차하는 상태. 병합 입력과 read 후보 수를 결정한다.
Compaction picker부채·크기·overlap·hot range를 보고 다음 병합 입력을 선택하는 정책 모듈.
Write amplification(WA)저장장치에 실제 쓴 byte ÷ 사용자가 논리적으로 쓴 byte.
Read amplification(RA)한 논리 read를 답하기 위해 확인한 run/file/block 또는 물리 read의 수.
Space amplification(SA)물리 저장 byte ÷ 최신 live logical data byte. obsolete version·tombstone·임시 output을 포함한다.
Tombstone삭제 사실을 더 오래된 value보다 먼저 보이게 하는 삭제 표식.
Snapshot특정 sequence 시점의 view. 오래된 version을 함부로 버리지 못하게 한다.
Compaction debt정책 목표를 회복하려면 앞으로 읽고 써야 할 pending bytes.
Write stallflush/compaction이 ingest를 따라가지 못할 때 쓰기를 늦추거나 멈춰 부채 폭주를 막는 backpressure.
Subcompaction큰 key range를 독립 구간으로 나눠 병렬 merge하는 방식.

2. 문제·입출력·제약 mental model

문제: flush만 계속하면 최신 값, 이전 값, tombstone이 수십 개 SST에 흩어진다. point get은 많은 run을 확인하고 range scan은 k-way merge를 반복하며 disk도 obsolete bytes로 찬다. 그러나 매 write마다 즉시 정리하면 foreground latency와 device write가 폭증한다.

먼저 묻는 제약설계 결과
write MB/s와 storage의 지속 compaction MB/s는?지속 가능 ingest, background concurrency, stall 임계값
point read·range scan·update 비율은?leveled/tiered/hybrid, Bloom·cache 예산
key range가 순차·균등·hotspot 중 무엇인가?overlap과 rewrite 편향, picker 우선순위
snapshot·TTL·삭제 보존 계약은?version/tombstone drop 가능 조건
disk headroom과 flash endurance는?temporary output 한도, WA 상한, emergency policy

핵심 식: foreground ingest가 λ bytes/s, compaction이 실제로 처리해야 하는 물리 write가 대략 λ·WA라면 device와 background CPU가 이를 지속해서 감당해야 한다. 순간 burst는 buffer가 흡수하지만 장기간 서비스율 μ가 도착률보다 작으면 debt(t+Δ)≈debt(t)+(λ·WA−μ)Δ로 커진다. 큰 buffer는 시간을 벌 뿐 불안정한 평균을 고치지 못한다.

3. Architecture 그림: compaction은 background transaction

① Observe debtlevel score, L0 files, pending bytes, disk headroom
↓ picker가 input과 모든 필수 overlap을 pin
② K-way mergeinternal key=(userKey, sequence↓, type) 순으로 stream
↓ snapshot/하위 level을 보고 version·tombstone drop
③ Build output새 SST·index·Bloom·checksum을 temp file에 작성·sync
↓ manifest/version edit를 원자적으로 install
④ Publish & retire새 reader는 output 사용, 옛 reader가 unpin 후 input 삭제

파일을 먼저 삭제하고 output을 만드는 순서는 금지다. prepare output → durability 확인 → metadata commit → reader epoch/refcount 종료 → reclaim 순서가 crash safety와 lock-free read를 동시에 지킨다.

4. Compaction ADT와 representation invariant

관리 연산: pick(), compact(inputs, snapshots), install(edit), reclaim(obsolete), pause/rateLimit(). 사용자는 Put/Get만 보지만 저장 엔진 correctness는 이 background ADT에 의존한다.

  1. 모든 input/output entry는 internal comparator 순으로 정렬돼 있다.
  2. non-L0 leveled level의 파일 key range는 정책상 서로 겹치지 않으며 picker는 다음 level의 모든 overlap을 포함한다.
  3. 각 user key에서 어떤 active snapshot이 관찰해야 하는 newest visible version도 제거하지 않는다.
  4. tombstone은 더 오래된 value가 input 밖의 하위 level에서 다시 나타날 수 없고 snapshot도 필요로 하지 않을 때만 제거한다.
  5. output file의 length·index·filter·checksum·sync가 성공하기 전에는 manifest가 output을 참조하지 않는다.
  6. 한 version edit는 input 제거와 output 추가를 함께 표현한다. reader는 old 또는 new version 중 하나를 본다.
  7. input은 old version reader가 모두 unpin할 때까지 물리 삭제하지 않는다.
  8. 실패·취소·ENOSPC에서는 installed set이 바뀌지 않으며 orphan temp만 안전하게 정리한다.

5. 정당성: per-key merge stream으로 증명하기

각 run이 internal key 순으로 정렬됐으므로 min-heap을 이용한 k-way merge는 전체 union을 같은 순서로 방출한다. 한 user key의 version은 sequence 내림차순으로 연속해 나온다.

  1. 현재 heap에는 각 run의 아직 소비하지 않은 최소 internal key가 하나씩 있다.
  2. heap 최소는 전체 미소비 원소 중 최소이므로 이를 출력하면 prefix가 계속 정렬된다.
  3. 같은 user key에서는 가장 최신 version부터 보며, 각 snapshot마다 첫 visible version만 보존하면 관찰 결과가 유지된다.
  4. 입력 전체와 더 낮은 level에 오래된 value가 없음을 증명한 tombstone만 버리면 삭제된 값이 부활하지 않는다.
  5. 모든 run이 소진되면 output은 input multiset에서 안전하게 제거 가능한 version만 제외한 동일 logical history다.
최소 반례 — tombstone 부활: L1에 DELETE(k, seq=9), L3에 PUT(k,v,seq=3)가 있다. L1→L2 compaction이 tombstone을 “삭제니까 불필요”라며 버리면 이후 Get(k)가 L3의 v를 찾아 삭제가 취소된다. bottommost-for-range 또는 하위 overlap 부재를 증명하기 전에는 tombstone을 남긴다.

Big-O만 보면 둘 다 선형 merge지만 device 관점에서는 몇 번 다시 쓰느냐가 핵심이다. leveled에서 작은 L의 새 data가 큰 L+1의 overlap을 반복해서 rewrite할 수 있다. tiered는 각 merge 단계에서 대체로 한 번씩 쓰지만 동시에 여러 run을 남긴다. 실제 WA 식은 fanout, level 수, key skew, compression, deletes, trivial move, picker와 workload에 따라 달라지므로 교과서 근사치를 운영 보장으로 쓰지 않는다.

8. 직접 구현: crash-safe compact 의사코드

def compact(plan, oldest_snapshot): inputs = version.pin(plan.file_ids) # deletion 방지 temp_outputs = [] try: stream = merge_by_internal_key(inputs) writer = new_temp_sst() for group in group_by_user_key(stream): for entry in retain_visible_versions(group, oldest_snapshot, plan.bottommost_for_range): writer.add(entry) if writer.should_cut_file(): temp_outputs.append(writer.finish_and_sync()) writer = new_temp_sst() if not writer.empty(): temp_outputs.append(writer.finish_and_sync()) verify_bounds_checksums(temp_outputs) edit = VersionEdit(add=temp_outputs, remove=inputs) manifest.append_and_sync(edit) # commit point version.install(edit) obsolete_queue.defer_until_unpinned(inputs) return OK except (IOError, NoSpace, Cancelled) as e: discard_uninstalled_temps(temp_outputs) return e finally: version.unpin(inputs)

코드 리뷰 포인트: partial output가 manifest에 들어가지 않는가, file number가 재사용되지 않는가, cancellation에도 input pin이 풀리는가, comparator가 모든 stage에서 같은가, range boundary에서 key group을 둘로 잘라 snapshot logic을 깨지 않는가를 본다.

9. 테스트: 결과뿐 아니라 transaction boundary를 때린다

  1. Differential: random Put/Delete/sequence/snapshot을 reference MVCC map과 compaction 전후 비교한다.
  2. Boundary: 같은 user key의 version이 파일 경계·subcompaction 경계·level boundary에 걸리게 한다.
  3. Tombstone: 하위 level에 old value가 있는/없는 경우, bottommost인/아닌 경우를 분리한다.
  4. Fault injection: input read, output append, checksum, fsync, manifest sync 각 지점에서 실패시키고 reopen 결과가 old 또는 new 중 하나인지 확인한다.
  5. ENOSPC: output 도중 disk full에서 live input과 manifest가 보존되고 temp cleanup이 idempotent인지 확인한다.
  6. Reader race: old version을 pin한 reader가 진행 중일 때 install/reclaim을 반복해 use-after-delete를 찾는다.
  7. Property: output 정렬, level overlap, key/value 결과, snapshot visibility, file reference count를 매 run 검증한다.

단순히 “compaction 3초”만 재면 판단할 수 없다. 고정 dataset과 동일 mutation trace에서 아래를 함께 기록한다.

모형 실험: 64개의 같은 크기 run을 4개씩 tiered merge하면 각 logical byte는 64→16→4→1의 세 단계 output에 기록된다. flush를 1회로 세면 이상적 총 WA는 약 4다. 반면 point miss는 compaction 전 최대 64 run, 완전 병합 후 1 run을 확인한다. 이것은 정책의 방향을 보여주는 산술 모델이지, leveled overlap·compression·tombstone·cache가 있는 실제 엔진의 수치가 아니다.

Benchmark 함정: page cache가 warm한지, compression이 같은지, compaction과 foreground가 같은 device를 공유하는지, dataset이 RAM보다 큰지, steady state까지 돌렸는지, logical value size와 key skew가 같은지 공개한다. 짧은 bulk load 결과를 24시간 steady workload에 일반화하지 않는다.

12. Production Best Practice

  1. 지속률부터 계산: peak가 아니라 장기 ingest×WA가 device의 지속 write와 CPU budget 아래인지 확인한다.
  2. 부채를 직접 관측: L0 file count, pending compaction bytes, oldest pending age, stall seconds를 SLO와 연결한다.
  3. headroom 예약: major/universal compaction은 input과 output이 동시에 존재한다. free disk 경보를 90% 이후에만 울리면 늦다.
  4. rate limit과 우선순위: background가 foreground p99를 망치지 않되, 지나친 throttling으로 debt가 발산하지 않게 closed-loop 조정한다.
  5. snapshot/iterator 수명 제한: 오래 열린 snapshot은 obsolete version과 파일 회수를 막아 SA를 높인다.
  6. subcompaction은 구간 균형 확인: key skew에서는 byte-balanced boundary와 병렬 I/O saturation을 측정한다.
  7. 설정 한 번에 하나: fanout, file size, trigger, job count, compression을 동시에 바꾸면 원인을 잃는다.
  8. 복구 리허설: kill -9, power-loss model, ENOSPC, corrupted file을 staging에서 반복하고 reopen 검증 시간을 잰다.

13. Anti-pattern과 놓치기 쉬운 함정

  • “L0 trigger를 크게 하면 stall이 사라진다”: 경보를 늦출 뿐 RA와 debt가 더 커질 수 있다.
  • “background job을 무조건 늘린다”: device queue·CPU·cache를 foreground와 경쟁시켜 p99가 악화될 수 있다.
  • “tombstone은 삭제 데이터라 즉시 버린다”: 하위 old value 부활 버그를 만든다.
  • “WA는 DB stats 한 숫자”: flush/WAL/compaction/device·replication 포함 범위를 명시하지 않으면 비교가 틀린다.
  • “평균 throughput만 본다”: install fsync·major merge·stall의 tail과 burst를 놓친다.
  • “manual full compaction으로 치료”: peak I/O와 temporary space가 장애를 확대할 수 있어 예산·중단 조건이 필요하다.

14. 대기업 면접 질문 3개와 답변 포인트

Q1. Leveled와 tiered compaction을 workload로 선택해 보세요.
먼저 read/write/scan 비율, latency SLO, disk headroom, SSD endurance, key skew를 묻는다. leveled는 non-overlap level로 RA·SA를 낮추지만 overlap rewrite로 WA가 커질 수 있다. tiered는 비슷한 run을 묶어 WA를 낮추지만 여러 run과 major merge 때문에 RA·SA·tail을 지불한다. Bloom·cache·hybrid도 함께 말한다.
Q2. Compaction 중 tombstone을 언제 삭제할 수 있나요?
해당 key range에서 더 낮은 level의 old value가 없고, 보존해야 할 snapshot/replica/backup이 그 삭제를 필요로 하지 않음을 증명해야 한다. 그렇지 않으면 delete marker 제거 후 old value가 부활한다. bottommost-for-range와 oldest snapshot 조건을 답한다.
Q3. write stall이 보이면 buffer와 thread를 늘리면 되나요?
먼저 ingest λ, observed WA, compaction throughput μ, pending bytes 추세와 device saturation을 본다. buffer는 burst를 늦추고 thread는 device가 여유 있을 때만 이득이다. λ·WA>μ이면 rate limit, WA 감소, device/capacity 확대, workload 분리 중 하나가 필요하다.
