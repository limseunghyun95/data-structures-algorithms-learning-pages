한 줄 요약
Insertion·selection·bubble sort는 모두 최악 Θ(n²)이지만, insertion은 inversion에 적응하고 online·stable, selection은 비교 수가 고정되지만 swap이 O(n), bubble은 adjacent swap 하나가 inversion 하나를 제거해 정당성과 비용을 가장 투명하게 보여준다.

4. Sorting ADT와 공통 representation invariant

ADT: sort(A,cmp)는 A와 동일한 identity multiset을 comparator 순서로 배치한다. stable이 계약이면 equal-key의 original index도 결과 조건이다.

  1. 모든 시점에 배열은 입력 identity의 permutation이다. 소실·복제·satellite 분리는 없다.
  2. comparator는 정렬 도중 변하지 않고 strict weak/total order 계약을 지킨다.
  3. 각 알고리즘의 sorted boundary 밖은 아직 미정이지만 boundary 안 invariant는 항상 참이다.
  4. stable 구현은 equal key를 swap/shift하지 않거나 original order를 명시적으로 tie-break한다.
  5. 범위 정렬이면 대상 밖 원소는 그대로이고 size/index arithmetic은 overflow하지 않는다.
알고리즘outer-loop invariant
Insertion반복 i 시작 시 A[0:i)는 원래 prefix의 stable sorted permutation.
Selection반복 i 시작 시 A[0:i)는 전체에서 가장 작은 i개이며 정렬됨.
Bubble한 pass 뒤 마지막 위치에는 현재 구간의 최댓값; 확정 suffix는 정렬되고 나머지보다 크거나 같음.

5. 정당성 증명 ① Insertion

Initialization: 길이 1 prefix는 정렬됐다. Maintenance: x보다 큰 prefix suffix만 오른쪽으로 한 칸 shift하고 생긴 위치에 x를 넣는다. 왼쪽은 ≤x, 오른쪽은 >x이므로 새 prefix가 정렬된다. 원소를 이동/복원하므로 permutation이다. equal에는 shift하지 않아 stable이다. Termination: i=n이면 전체 배열이 stable sorted permutation이다.

정확한 비용: shift 하나는 x와 앞 원소 사이 inversion 하나를 제거한다. 따라서 shift 수는 I. loop/insert overhead를 더해 Θ(n+I), best I=0이면 Θ(n), reverse면 I=n(n−1)/2라 Θ(n²)이다. 새 원소가 도착할 때 sorted prefix에 삽입할 수 있어 online이다.

6. 정당성 증명 ② Selection

Initialization: 빈 prefix는 가장 작은 0개다. Maintenance: suffix 전체를 scan해 최솟값 m을 찾는다. m을 A[i]와 바꾸면 새 prefix는 이전의 가장 작은 i개 + 다음 최솟값이므로 가장 작은 i+1개이며 정렬된다. Termination: n−1개가 확정되면 마지막 원소도 자동으로 최대다.

정확한 비용: 입력 분포와 무관하게 비교 수는 (n−1)+(n−2)+…+1=n(n−1)/2. swap은 최대 n−1회다. 따라서 비교가 비싸면 nearly sorted 이득이 없지만, record write가 매우 비싼 특수 cost model에서는 적은 swap이 관찰 포인트다.

불안정 최소 반례: [(2,a),(2,b),(1,x)]에서 (1,x)를 첫 칸과 swap하면 [(1,x),(2,b),(2,a)]. key는 정렬됐지만 equal 2의 a/b 순서가 뒤집힌다. 단순 swap selection은 stable이 아니다.

7. 정당성 증명 ③ Bubble

왼쪽부터 인접 pair를 비교해 역전이면 swap한다. pass 중 지금까지 본 최댓값은 매 비교마다 오른쪽으로 이동하므로 pass 끝에는 현재 구간의 최댓값이 마지막에 있다. 그 위치를 확정 suffix에 넣고 반복하면 전체가 정렬된다.

inversion potential: 인접 역전 pair를 swap하면 그 두 원소의 inversion 하나만 제거하고 다른 원소와의 상대 순서는 바뀌지 않는다. 따라서 strict > bubble의 swap 수는 정확히 I이고 종료 시 I=0이라 정렬됐다. equal은 swap하지 않아 stable이다. last-swap boundary와 no-swap early exit로 sorted input은 n−1 비교 후 끝난다.

이것이 bubble의 가장 큰 교육적 가치다. progress measure I가 매 swap마다 1 감소해 종료와 비용을 동시에 증명한다. 그러나 한 inversion당 swap과 두 slot write를 수행하므로 random/reverse large input에는 이동량이 지나치게 크다.

8. 직접 구현: 세 알고리즘의 차이가 보이는 코드

def insertion(a): for i in range(1, len(a)): x, j = a[i], i while j > 0 and x.key < a[j-1].key: # equal shift 안 함 a[j] = a[j-1]; j -= 1 a[j] = x def selection(a): for i in range(len(a)-1): m = i for j in range(i+1, len(a)): if a[j].key < a[m].key: m = j if m != i: a[i], a[m] = a[m], a[i] # unstable 가능 def bubble(a): end = len(a) while end > 1: last = 0 for j in range(1, end): if a[j].key < a[j-1].key: # equal swap 안 함 a[j-1], a[j] = a[j], a[j-1] last = j if last == 0: break end = last

코드 리뷰: equal 비교에 <=를 쓰면 insertion/bubble 안정성이 깨진다. key 함수를 inner loop에서 반복 호출하면 비싼 parsing이 Θ(n²)번 일어난다. key cache는 시간을 줄이지만 O(n) memory와 fail-before-mutate 의미를 추가한다.

10. 테스트 전략

  1. Postcondition: adjacent sortedness와 identity multiset permutation을 따로 검사한다.
  2. Stability: record를 (key,originalIndex)로 만들어 key별 index가 증가하는지 검사한다.
  3. Invariant hook: outer loop마다 insertion prefix, selection prefix, bubble suffix 명제를 assert한다.
  4. Exact counter: n=0..9 모든 permutation에서 comparison/swap 수와 formula를 대조한다.
  5. Distribution: sorted, reverse, random, all-equal, few-key, 1% adjacent swaps를 반드시 분리한다.
  6. Comparator property: irreflexive·asymmetric·transitive와 overflow/NaN/locale를 검사한다.
  7. Failure: key extraction/comparator 예외 뒤 partially mutated 상태가 API 계약과 맞는지 확인한다.

12. 왜 실무에서 insertion은 살아남고 bubble은 거의 사라졌나

Modern hybrid sort는 큰 문제를 divide/merge/partition한 뒤 작은 run에서 insertion 또는 binary insertion을 사용한다. 짧은 코드, contiguous shift, low overhead, 이미 일부 정렬된 run 활용 때문이다. OpenJDK TimSort도 작은 배열과 짧은 run을 binary insertion으로 확장한다.

Selection은 write-minimization 사고를 가르치지만 cache-friendly한 현대 library sort를 이기는 일반 목적 선택은 아니다. Bubble의 adjacent repair는 inversion 증명과 교육에는 훌륭하지만 같은 I에 대해 insertion은 block shift 형태로 더 단순하고 write/branch가 적기 쉽다. “배운다”와 “production 기본값으로 쓴다”를 구분한다.

14. Production Best Practice

  1. 직접 elementary sort를 배포하기 전에 표준 library의 stability·worst case·memory 계약을 우선 사용한다.
  2. hybrid cutoff는 상수 16/32를 복사하지 말고 record width·key cost·CPU별 benchmark로 정한다.
  3. small/nearly sorted run에는 insertion을 고려하고 큰 general input에는 non-quadratic 알고리즘을 쓴다.
  4. write가 비싸면 comparison과 write를 별도 계수하되 selection의 Θ(n²) read/comparison 비용도 포함한다.
  5. stable이 business contract면 equal-key original order를 회귀 테스트에 넣고 library 변경 때 검증한다.
  6. untrusted 입력에는 n·time·memory cap과 cancellation을 두어 algorithmic DoS를 막는다.
  7. 성능 log에는 n뿐 아니라 inversion/run/duplicate 비율과 C/W/moved bytes를 남긴다.

15. Anti-pattern

  • O(n²)이니 셋은 같다: best case, exact comparisons, writes, stability, online 성질이 다르다.
  • binary search insertion이면 O(n log n): 위치 비교는 줄어도 array shift는 Θ(n²)일 수 있다.
  • selection은 항상 stable: 최솟값 swap이 equal record를 가로질러 순서를 뒤집는다.
  • bubble no-swap flag 누락: sorted input에서도 불필요한 Θ(n²) 비교를 한다.
  • equal에 swap/shift: <= 하나로 stability와 all-equal best case를 망친다.
  • large request에 교육용 구현: quadratic algorithmic DoS와 timeout을 만든다.

16. 대기업 면접 질문 3개와 답변 포인트

Q1. 세 알고리즘이 모두 O(n²)인데 차이가 있나요?
Insertion은 Θ(n+I), stable·adaptive·online이고 shift=I다. Selection은 항상 n(n−1)/2 비교지만 swap≤n−1, 보통 unstable이다. Optimized bubble은 best Θ(n), stable, swap=I지만 adjacent swap write가 커 일반 실무에서는 거의 쓰지 않는다.
Q2. insertion sort가 library 내부에서 쓰이는 이유는?
작은 partition/run에서는 n log n 알고리즘의 recursion/merge/partition overhead보다 짧은 contiguous shift가 싸고, 이미 일부 정렬됐으면 Θ(n+I)로 빠르다. cutoff는 구현·record·hardware에 맞춰 측정한다.
Q3. bubble sort의 정당성을 inversion으로 증명해 보세요.
인접 역전 swap은 다른 원소의 상대 순서를 건드리지 않고 해당 inversion 하나만 제거한다. I는 음이 아닌 정수이며 swap마다 1 감소하고, pass에서 swap이 없으면 I=0이므로 정렬됐다. strict 비교면 equal을 swap하지 않아 stable이다.
