한 줄 요약
chaining은 bucket 밖의 entry container로 충돌을 흡수하고, open addressing은 table 안의 probe sequence로 빈 slot을 찾는다. 같은 expected O(1)이라도 α 민감도·allocation·locality·삭제·reference 안정성은 전혀 다르다.

1. 초보자를 위한 용어 사전

Collision resolution서로 다른 key가 같은 첫 bucket을 가질 때도 mapping을 잃지 않고 저장·탐색하는 규칙.
Separate chainingbucket마다 entry들의 별도 chain/container를 두는 방식. 한 bucket에 여러 key가 들어갈 수 있다.
Open addressing모든 entry를 slot array 안에 두고 충돌 시 정해진 후보 위치들을 차례로 검사하는 방식.
Probeopen addressing에서 slot 하나를 읽고 상태·key를 검사하는 1회 동작.
Probe sequencekey마다 검사할 slot 순서 p(k,0),p(k,1),…. table의 모든 slot을 중복 없이 방문할 수 있어야 한다.
Linear probingp(k,j)=(h(k)+j) mod m으로 연속 slot을 보는 가장 단순한 open addressing.

Pointer stability삽입·rehash 뒤에도 보관한 원소 주소가 유효한 성질. flat table은 이동 때문에 보통 약하다.
Failure atomicityallocation·capacity 오류가 나도 추상 Map이 호출 전 상태로 보존되는 성질.

Lookup 흐름 비교: chaining은 hash → bucket pointer → chain equality scan, open addressing은 hash → p(k,0) → p(k,1) → … → key 또는 EMPTY다. “O(1)” 뒤의 실제 memory access graph가 다르다.

4. 같은 Map ADT, 다른 abstraction function

공통 ADT: 유한 부분함수 M: K ⇀ V. get은 FOUND/NOT_FOUND, put은 INSERTED/REPLACED/FULL·OOM, delete는 REMOVED/NOT_FOUND를 구분한다. 같은 key는 최대 하나이며 iteration order는 계약하지 않는다.

5. Representation invariant

Chaining RI

  1. m>0, bucket array 길이는 m, size=Σ chain_length(i).
  2. 모든 entry e는 정확히 bucket[h(e.key)]에 한 번 존재한다.
  3. equality 기준 중복 key가 없고, chain은 cycle 없이 종료한다.
  4. node 소유권·allocator가 명확하며 erase된 node 주소는 다시 사용하지 않는다.

Open addressing RI

  1. 0≤size<m, size=#OCCUPIED; 삽입 가능한 table에는 최소 한 EMPTY가 있다.
  2. 모든 OCCUPIED key k는 자신의 probe sequence 위에 정확히 한 번 존재한다.
  3. k의 home에서 저장 slot까지 lookup이 만나는 앞선 slot에는 EMPTY가 없다. DELETED는 통과한다.
  4. probe sequence는 최대 m회 안에 모든 후보를 중복 없이 방문하거나 명시적으로 종료한다.
  5. EMPTY, OCCUPIED, DELETED control state와 payload lifetime이 일치한다.

공통 RI: equality와 hash에 쓰는 key field는 저장 중 불변이고 x==y ⇒ hash(x)==hash(y)다. 표현만 바꿔도 이 계약은 바뀌지 않는다.

6. Lookup 정당성 증명

Chaining: k가 존재하면 RI에 의해 B[h(k)] 안에 있다. lookup이 그 chain의 모든 entry를 equality로 검사하므로 유일한 mapping을 찾는다. chain 끝까지 없으면 다른 bucket에 있을 수 없으므로 NOT_FOUND가 맞다.

Open addressing: k가 slot p(k,j)에 저장됐다고 하자. 삽입 당시 앞선 p(k,0..j-1)은 OCCUPIED 또는 재사용 가능한 DELETED였고 EMPTY였다면 거기에 저장됐을 것이다. 삭제가 그 prefix를 EMPTY로 바꾸지 않는다는 RI 아래 lookup은 같은 순서를 따라 k에 도달한다. 먼저 EMPTY를 만나면 그 뒤에 k가 저장됐을 수 없으므로 NOT_FOUND다.

최소 반례: m=8, linear probing에서 h(A)=h(B)=1이라 A는 slot 1, B는 slot 2에 있다. A를 EMPTY로 지우면 B lookup은 slot 1에서 멈춰 거짓 NOT_FOUND를 낸다. A 자리를 DELETED로 두거나 cluster를 올바르게 재배치해야 한다.

7. Complexity: 같은 expected O(1)의 다른 조건

축ChainingOpen addressing

* MIT의 uniform hashing 분석에서 unsuccessful search/insert의 기대 probe 상한. linear probing은 독립 uniform permutation 가정을 만족하지 않고 primary clustering으로 더 나빠질 수 있다. α→1이면 분모가 0에 가까워진다.

Amortized 축: 양쪽 모두 resize/rehash가 한 번에 Θ(n)일 수 있고 geometric growth라면 긴 연산열에 상각할 수 있다. expected는 hash/probe 분포에 대한 평균, amortized는 연산열 합에 대한 보장이다. p99 한 번을 보장하지 않는다.

8. 직접 구현: 두 lookup의 핵심

typedef struct Node {
  uint64_t key, value;
  struct Node *next;
} Node;

bool chain_get(const Map *t, uint64_t k, uint64_t *out) {
  for (Node *p = t->buckets[index(k)]; p; p = p->next) {
    if (p->key == k) { *out = p->value; return true; }
  }
  return false;
}

typedef enum { EMPTY, OCCUPIED, DELETED } State;
typedef struct { uint64_t key, value; State state; } Slot;

bool flat_get(const Flat *t, uint64_t k, uint64_t *out) {
  size_t i = index(k);
  for (size_t probes = 0; probes < t->m; ++probes) {
    const Slot *s = &t->slots[i];
    if (s->state == EMPTY) return false;       // proof의 종결점
    if (s->state == OCCUPIED && s->key == k) {
      *out = s->value; return true;
    }
    i = (i + 1) & (t->m - 1);                 // m은 2의 거듭제곱
  }
  return false;                                // corrupt/full에도 유한 종료
}

놓치기 쉬운 조건: mask wrap은 m이 2의 거듭제곱일 때만 modulo와 같다. 임의 m에는 %m 또는 다른 검증된 reduction을 쓴다. key 0을 EMPTY sentinel로 겸용하면 0을 저장할 수 없으므로 별도 state/control byte가 안전하다.

9. Insert·delete·allocation의 transaction 경계

경로PrepareCommit
chain put new중복 확인, node/value 구성bucket head 연결 후 size++
flat put new전체 probe, first deleted 기억, capacity 확인payload 완성 후 state=OCCUPIED, size++
chain deleteowner link와 target 찾기unlink, size--, value/node destroy
flat deletetarget 찾기payload destroy 후 DELETED, size--; tombstone count++

state를 OCCUPIED로 먼저 공개하고 payload construction이 실패하면 reader가 미완성 값을 볼 수 있다. concurrent map이라면 memory ordering과 publication linearization을 별도 설계한다. 이 단일-thread 구현을 lock-free라고 확대 해석하지 않는다.

10. 테스트: reference model + RI + failure injection

  1. 두 구현에 같은 random put/get/delete trace를 넣고 reference dict와 mapping·size를 매 단계 비교한다.
  2. m=1/2/8, key 0·최댓값, duplicate replacement, missing, wrap-around cluster를 포함한다.
  3. 각 prefix 뒤 chain의 bucket 소속·cycle·count, flat의 state count·probe reachability·key uniqueness를 검사한다.
  4. home이 같은 A/B에서 A 삭제 후 B를 찾는 최소 반례로 EMPTY/DELETED 혼동을 잡는다.
  5. allocation N번째 실패, value constructor 예외, capacity 산술 overflow를 주입하고 추상 map snapshot이 유지되는지 확인한다.
  6. ASan/UBSan, leak check, randomized differential test를 통과한 binary와 benchmark binary를 분리한다.

이번 검증: C11 두 구현을 Apple clang 21.0.0의 -Wall -Wextra -Werror와 ASan/UBSan으로 실행했다. 131,072·209,715개 entry의 hit/miss 및 destroy가 오류·누수 보고 없이 통과했다.

11. Benchmark 결과: α가 open addressing을 압박한다

환경: Apple clang 21.0.0 -O3, arm64 macOS 26.5.2, m=262,144, 같은 64-bit mixer·key 순서, random-order 전체 hit lookup, 각 5회 median. chaining은 node-per-entry, flat은 24-byte slot의 단순 linear probing이다.

0.51.2491.4980.501 / 2.5071.228 / 1.343
0.81.3993.0050.802 / 12.9652.351 / 3.493

해석: α=0.8에서 linear probing miss가 cluster 끝까지 걷느라 급증했다. flat이 패배한 것은 “open addressing은 느리다”는 결론이 아니라 이 24-byte AoS slot·linear probe 구현의 결과다. Swiss table류는 작은 control byte group과 SIMD lookup으로 memory traffic을 줄인다.

메모리 근사: 이번 C ABI에서 node와 slot은 각각 24 bytes다. allocator metadata를 빼도 chain은 m×8+n×24, flat은 m×24. α=0.5에서는 약 5.0MiB/6.0MiB, α=0.8에서는 약 6.8MiB/6.0MiB다. 실제 allocator·alignment·control layout을 포함해 resident bytes를 측정해야 한다.

benchmark 주의: build·RNG·allocation을 timed region에서 빼고 hit/miss를 따로 잰다. α, key/value 크기, delete churn, tombstone 수, chain/probe p95·max, iteration, allocator, rehash, hardware counter를 기록한다. 평균 probe와 wall time의 상관을 확인하고 한 구현의 최적화 수준 차이를 알고리즘 차이로 오인하지 않는다.

12. Memory·locality·reference lifetime

  • Node chaining: bucket pointer 뒤 node를 따라가므로 dependent cache miss와 allocator overhead가 생긴다. 대신 value 주소를 안정적으로 유지하기 쉽고 큰 value를 rehash 때 복사하지 않는다.
  • Bucket vector chaining: bucket별 작은 contiguous storage는 node보다 locality가 좋지만 vector growth와 erase 이동, bucket별 slack이 생긴다. chaining=linked list로 고정하지 않는다.
  • Flat open addressing: control·key·value가 가까우면 prefetch/SIMD에 유리하고 allocation 수가 적다. 큰 value는 probe마다 불필요한 cache line을 읽을 수 있다.
  • SoA control: state/fingerprint를 작은 control byte array로 분리하면 여러 후보를 먼저 필터링하고 실제 key/value load를 줄일 수 있다.
  • Rehash: flat table은 원소가 이동해 pointer/iterator가 무효화될 수 있다. C++ 표준 unordered container는 rehash가 iterator를 무효화하지만 element pointer/reference는 유지하는 node 계열 계약을 갖는다. container마다 문서를 확인한다.
  • 합성: flat index + heap-owned value는 lookup locality와 value 주소 안정성을 절충하지만 pointer indirection·allocation을 다시 추가한다.

16. 대기업 면접 질문 3개와 답변 포인트

Q1. chaining과 open addressing 중 무엇을 고르겠습니까?
Map 계약 → hit/miss/delete·α → key/value bytes → locality/allocation → pointer stability → resize tail·OOM → 보안 분포 → benchmark 순으로 답한다. 작은 value·lookup 중심이면 flat을 먼저 측정하고, 강한 주소 안정성·큰 value면 node/indirection을 검토한다.
Q2. open addressing 삭제에서 EMPTY로 바꾸면 왜 틀리나요?
같은 home의 뒤 key까지 이어지는 probe prefix를 끊어 거짓 NOT_FOUND를 만든다. DELETED는 lookup을 통과시키고 insert가 재사용하며, backshift는 probe 불변식을 보존해 재배치해야 한다. tombstone 누적 지표와 rehash 정책까지 말한다.
Q3. open addressing이 cache-friendly라는데 benchmark에서 느린 이유는?
“flat”은 충분조건이 아니다. α=0.8, linear clustering, 24-byte AoS slot, random hit/miss가 probe traffic을 키웠다. control-byte SoA·SIMD·better probing 같은 구현 차이와 동일 hash/key/contract의 공정 비교, p95 probe·hardware counter를 제시한다.
