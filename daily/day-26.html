한 줄 요약
Trie는 key의 symbol sequence를 root부터의 path로 표현해 길이 L인 exact/prefix 탐색을 key 개수 N보다 L에 묶지만, 실제 성능은 alphabet 크기·child 표현·Unicode 정규화·출력량·cache locality가 결정한다.

5. String Map ADT와 representation invariant

ADT: put(key,value), get, remove, keysWithPrefix(prefix,limit), longestPrefixOf(query). duplicate key의 replace/merge, empty key, empty prefix, ordering, limit=0도 계약이다.

  1. RI-1 path-label: root에서 node v까지 edge label을 연결한 문자열이 v의 유일한 prefix다.
  2. RI-2 deterministic edge: 한 node에서 같은 symbol로 나가는 child는 최대 하나다.
  3. RI-3 terminal: terminal(v) iff path(v)가 저장된 완전한 key다.
  4. RI-4 reachability: 모든 live node는 root에서 정확히 한 path로 도달하며 cycle·shared child가 없다.
  5. RI-5 metadata: subtreeCount(v)는 v subtree의 terminal 수, cached top-k는 그 subtree key만 포함하며 score/version 정책과 일치한다.
  6. RI-6 canonical form: 모든 key와 query는 명시한 encoding·normalization·case 정책을 통과한 symbol sequence다.
  7. Radix 추가 RI: edge label은 비어 있지 않고, 한 node의 서로 다른 edge는 첫 symbol이 다르며 불필요한 nonterminal degree-1 node가 없다.

6. Prefix search 정당성: soundness와 completeness

prefix p의 symbol을 따라 node v를 찾고 v subtree의 terminal node를 수집한다.

  • Soundness(거짓 결과 없음): v까지 path가 p이고 descendant까지 추가 edge만 붙으므로 반환 key는 모두 p로 시작한다.
  • Completeness(누락 없음): p로 시작하는 저장 key k의 처음 |p| symbols는 deterministic edge에 의해 같은 v에 도달한다. 나머지 symbols가 v 아래 path이므로 terminal(k)는 반드시 v subtree에 있다.
  • 종료: 유한 acyclic tree와 방문 budget에서 traversal은 끝난다. 전체 결과를 요구하면 출력 크기만큼의 시간은 피할 수 없다.

최소 반례: car, card를 저장하고 terminal을 leaf로만 판정하면 contains("car")가 false가 된다. car node의 “key 종료”와 “child 존재”를 독립 상태로 둬야 한다.

9. Radix split의 proof obligation

기존 edge shells에 shellfish를 넣으면 longest common prefix shell에서 edge를 split하고 suffix s, fish 두 edge를 만든다. split 전후 root→terminal label concatenation 집합이 같아야 한다.

  1. LCP 길이는 두 label 범위 안이며 새 intermediate edge는 non-empty다.
  2. 기존 child·terminal·metadata는 기존 suffix로 이동한다.
  3. 새 key suffix가 empty면 intermediate가 terminal, 아니면 새 child를 만든다.
  4. allocation을 모두 성공시킨 뒤 link를 바꾸어 OOM 때 원본을 보존한다.

10. 직접 구현·테스트·benchmark

C11로 lowercase 26-way dense array와 존재 edge만 저장하는 linked sparse trie를 같은 index arena에 구현했다. 20만 unique 16-byte key(search 공통 prefix), 100만 hit query를 5회 측정했다.

dense는 약 4.67배 메모리를 쓰고 조회는 약 6.28배 빨랐다. sparse 조회는 query당 평균 59 edge scan이었다. 이는 linked list라는 한 구현의 결과이지 모든 sparse 표현의 결론이 아니다. sorted vector·bitmap·radix를 같은 workload로 비교해야 한다.

검증: invalid byte 거부, exact lookup, prefix subtreeCount, dense↔sparse differential test와 ASan/UBSan을 통과했다. benchmark는 arm64 macOS·Apple clang 21.0.0 -O3의 microbenchmark라 allocator, corpus, miss ratio, thermal, CPU counter와 p95를 추가해야 한다.

11. Unicode: “문자 하나”를 먼저 정의하라

UTF-8 byte trie는 유효한 정규화 UTF-8에 대해 정확히 동작하고 compact할 수 있지만, 복잡도 L은 사용자 글자 수가 아니라 byte 수다. UTF-16 code unit trie도 surrogate pair를 둘로 본다. code point trie는 의미가 낫지만 alphabet을 거대한 dense array로 만들 수 없다.

필수 반례: 화면상 같은 é가 precomposed U+00E9 또는 e+U+0301로 들어올 수 있다. normalize하지 않으면 서로 다른 path·prefix 결과가 된다. NFC/NFKC, case folding, locale 정책은 product semantics이므로 무작정 NFKC로 정보를 잃지 말고 저장·조회 양쪽에 버전까지 고정한다.

한글도 완성형 syllable과 Jamo sequence가 달라질 수 있다. grapheme cluster prefix가 필요한 UI라면 Unicode segmentation까지 별도 계약으로 두고 표준 library를 사용한다.

12. Autocomplete는 trie traversal만으로 끝나지 않는다

  • 출력 폭발: empty prefix나 a가 수백만 key를 가리킬 수 있다. limit·deadline·pagination과 maximum visited nodes를 둔다.
  • Ranking: lexicographic 결과와 popularity top-k는 다른 ADT다. 각 node에 top-k cache를 두면 query는 빨라지지만 score update가 ancestor 전부를 건드린다.
  • Freshness: static base trie + small mutable delta + periodic rebuild로 read locality와 update 비용을 분리할 수 있다.
  • Personalization: global candidates를 먼저 제한한 뒤 user/context model로 rerank한다. 개인 정보를 trie key에 그대로 복제하지 않는다.
  • Distributed: 첫 byte/range shard는 hot prefix skew를 만든다. replica/cache와 load shedding, versioned snapshot을 함께 설계한다.

14. 실무 Best Practice

  1. 먼저 String Map/Prefix Index ADT와 normalization·ordering·empty·limit 계약을 쓴다.
  2. 실제 corpus에서 depth·degree·prefix fan-out·key bytes·hot prefix 분포를 측정한다.
  3. 상위 hot node는 dense/bitmap, 깊은 low-degree node는 packed sparse/radix인 hybrid를 고려한다.
  4. pointer 대신 arena index·packed immutable arrays로 locality, serialization, snapshot loading을 개선한다.
  5. terminal과 child 존재를 분리하고 subtreeCount/top-k metadata를 validator로 재계산한다.
  6. Unicode 표준 library와 conformance data를 쓰고 canonicalizer 버전을 migration 계약에 포함한다.
  7. query에서 input length, output k, node visits, deadline을 모두 제한한다.
  8. bytes/node, cache miss, visited nodes, prefix fan-out, stale snapshot, p50/p99를 관측한다.

16. 대기업 면접 질문 3개와 답변 포인트

Q1. Trie prefix search가 왜 정확한지 증명하세요.
path-label RI와 deterministic edge를 선언한다. prefix node의 descendant는 p 뒤에 suffix만 붙으므로 sound하고, p로 시작하는 모든 key는 처음 |p| symbol에서 같은 node에 도달하므로 complete하다. 시간은 O(P+visited+output)이라고 답한다.
Q2. Hash map, balanced tree, trie 중 autocomplete에는 무엇을 고르나요?
exact-only면 hash, ordered/range general key면 tree, prefix/LPM과 공유 prefix가 핵심이면 trie다. 그러나 R-way memory, Unicode, output fan-out, update/top-k 비용을 실제 operation mix·corpus·p99로 비교한다.
Q3. Unicode trie가 production에서 틀리는 대표 원인은?
byte/code unit/code point/grapheme 혼동과 write/query normalization·case-folding 불일치다. canonical equivalent 문자열이 다른 path가 되는 반례를 들고, 표준 canonicalizer·버전·locale·length/output 제한·migration을 답한다.
