한 줄 요약
같은 Θ(1) 연산을 제공해도 representation에 따라 resize spike, allocation 수, memory footprint, cache locality와 tail latency가 달라진다. 공정한 benchmark는 같은 ADT 계약·입력·오류 의미부터 고정한다.

3. 문제·입출력·제약 mental model

실험 질문: 같은 Stack ADT를 Python list와 singly-linked Node로 구현했을 때 push-N/pop-N workload의 시간과 retained memory가 어떻게 달라지는가?

  • 입력: 미리 만든 동일한 object reference N개. 값 생성 비용은 timed region 밖에 둔다.
  • 연산 trace: N회 push 후 empty까지 N회 pop. 다음 실험에서는 70% push/30% pop burst처럼 production 비율을 별도 적용한다.
  • 출력: 두 구현의 pop sequence, 최종 length, 예외 type/message가 같아야 한다.
  • 측정: run당 시간의 repeat vector와 min/median, N개 유지 시 traced current/peak memory.
  • 고정 조건: Python implementation/version, OS·CPU architecture, GC on/off, N, repeat/number, background load.
가설: 두 표현 모두 push/pop이 점근적으로 Θ(1)이지만, array-backed는 대부분의 push에서 Node allocation이 없고 reference slot이 모여 있어 상수가 작을 가능성이 높다. linked는 resize copy가 없지만 매 push마다 Node를 할당한다. 측정은 이 가설을 검증할 뿐 증명하지 않는다.

4. Stack ADT와 두 abstraction function

Abstract value: top부터 bottom까지의 유한 sequence ⟨top, …, bottom⟩. push(x)는 앞에 x를 붙이고, pop()은 첫 값을 제거·반환하며, peek()은 제거 없이 첫 값을 반환한다. empty pop/peek는 IndexError다.

표현Concrete state와 AFRI
ArrayStack_items=[bottom,…,top]; AF는 list를 역순으로 읽는다._items는 private list이며 size는 len(_items)와 같다.
LinkedStack_head→top→…→bottom→None; AF는 chain 순서 그대로다.chain은 finite·acyclic이고 Node 수=_size, size=0 iff head=None.

두 class가 같은 method 이름을 가졌다는 것만으로 같은 ADT가 아니다. 반환 순서, empty 오류, mutation 후 상태가 모든 허용 operation trace에서 같아야 observationally equivalent, 즉 client가 관찰로 구현을 구분할 수 없다고 말할 수 있다.

5. 직접 구현: 오류 의미와 실패 원자성까지 통일

class ArrayStack:
    __slots__ = ("_items",)

    def __init__(self):
        self._items = []

    def __len__(self):
        return len(self._items)

    def push(self, value):
        self._items.append(value)

    def pop(self):
        if not self._items:
            raise IndexError("pop from empty stack")
        return self._items.pop()

    def peek(self):
        if not self._items:
            raise IndexError("peek from empty stack")
        return self._items[-1]


class _Node:
    __slots__ = ("value", "next")

    def __init__(self, value, next_node):
        self.value = value
        self.next = next_node


class LinkedStack:
    __slots__ = ("_head", "_size")

    def __init__(self):
        self._head = None
        self._size = 0

    def __len__(self):
        return self._size

    def push(self, value):
        new_size = self._size + 1
        new_head = _Node(value, self._head)  # allocate first
        self._head = new_head
        self._size = new_size

    def pop(self):
        node = self._head
        if node is None:
            raise IndexError("pop from empty stack")
        new_size = self._size - 1
        self._head = node.next
        self._size = new_size
        return node.value

    def peek(self):
        if self._head is None:
            raise IndexError("peek from empty stack")
        return self._head.value

__slots__는 instance별 attribute dictionary를 없애 Node overhead를 줄이지만 Node 한 개씩의 allocation과 pointer chasing은 남는다. Linked push는 integer와 Node를 먼저 준비한 뒤 head/size를 commit해 allocation 실패 시 기존 RI가 보존되게 한다.

6. 정당성: representation simulation

  1. 초기화: empty list와 head=None,size=0은 모두 abstract empty sequence를 나타내며 RI를 만족한다.
  2. push: array의 끝에 x를 append하면 역순 AF의 첫 값이 x가 된다. linked는 x Node를 새 head로 연결해 chain 첫 값이 x가 된다. 둘 다 abstract ⟨x⟩ + S다.
  3. pop: array 마지막 값과 linked head 값은 각각 AF의 첫 값이다. 제거 후 두 표현 모두 나머지 S를 나타내며 size가 1 감소한다.
  4. peek/len: state를 바꾸지 않고 AF의 첫 값/sequence 길이를 반환한다.
  5. 오류: abstract sequence가 empty일 때 두 표현 모두 mutation 전에 같은 IndexError를 낸다.
최소 반례: ArrayStack에서 top을 index 0으로 정해 insert(0,x)/pop(0)을 쓰면 LIFO 결과는 맞아도 매번 reference shift가 발생해 Θ(n)이 된다. ADT correctness만 같고 performance contract는 달라지는 가장 작은 설계 실수다.

CPython의 현재 listobject.c는 append 연산열이 linear-time amortized behavior를 갖도록 mild proportional over-allocation을 한다. 이는 Python 언어 계약이 아닌 CPython 구현 세부이므로 성장 계수와 benchmark 결과를 다른 Python runtime에 그대로 일반화하면 안 된다.

8. 공통 테스트: benchmark 전에 correctness gate

def run_trace(factory):
    stack = factory()
    observed = [len(stack)]
    for value in ("A", "B", "C"):
        stack.push(value)
        observed.append(stack.peek())
    while stack:
        observed.append(stack.pop())
    observed.append(len(stack))
    try:
        stack.pop()
    except IndexError as error:
        observed.append((type(error), str(error)))
    return observed

expected = [0, "A", "B", "C", "C", "B", "A", 0,
            (IndexError, "pop from empty stack")]
assert run_trace(ArrayStack) == expected
assert run_trace(LinkedStack) == expected

여기에 seed를 고정한 random operation trace를 만들고, 기대 결과를 제공하는 기준 구현인 Python list를 oracle로 사용한다. 매 operation 뒤 len과 peek, 모든 pop 결과를 비교한다. benchmark가 빨라도 trace가 다르면 그 구현은 후보에서 탈락한다.

9. 재현 가능한 시간·memory harness

import gc, statistics, timeit, tracemalloc

def churn(factory, values):
    stack = factory()
    for value in values:
        stack.push(value)
    while stack:
        stack.pop()

values = tuple(range(100_000))  # setup outside timed region
for factory in (ArrayStack, LinkedStack):
    samples = timeit.repeat(
        lambda: churn(factory, values), repeat=9, number=3)
    per_run = [seconds / 3 for seconds in samples]
    print(factory.__name__, min(per_run), statistics.median(per_run))

def retained(factory, values):
    gc.collect()
    tracemalloc.start()
    stack = factory()
    for value in values:
        stack.push(value)
    current, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    return current, peak
  • timeit은 기본적으로 timing 동안 GC를 끈다. 독립 측정 비교에는 좋지만 GC가 workload 일부라면 setup에서 명시적으로 켠 별도 실험도 해야 한다.
  • 공식 문서는 repeat 중 가장 작은 값이 외부 간섭이 적은 lower bound라고 설명한다. production tail 판단에는 전체 vector와 p95/p99도 따로 본다.
  • tracemalloc은 traced Python allocation의 current/peak다. allocator가 OS에서 잡아 실제 RAM에 머문 process memory인 RSS 전체나, 저장 값(payload)이 외부 native memory에 둔 공간과 같지 않다.
  • sys.getsizeof(stack)만 비교하면 참조 대상 Node/list buffer를 제외하는 shallow size 함정에 빠진다.

11. Error handling과 production Best Practice

  • 같은 실패 계약: empty pop/peek의 exception type과 message를 통일한다. 한 구현만 None을 반환하면 benchmark 대상 ADT가 다르다.
  • 실패 원자성: allocation이 성공하기 전에 head/size를 바꾸지 않는다. MemoryError 후에도 기존 Stack이 유효해야 한다.
  • 불변식 검사: debug/test에서 object identity(값이 아니라 같은 object인지)를 기록하는 set으로 linked chain의 cycle과 실제 Node 수=_size를 검사한다. Θ(n) rep_ok를 매우 자주 호출되는 hot operation마다 production에서 실행하지 않는다.
  • 동시성: 두 class 모두 ADT 수준의 thread safety를 약속하지 않는다. 특정 CPython method가 중간 상태를 노출하지 않는 atomic 연산처럼 보여도, 여러 단계를 묶은 compound push-if-empty 계약은 lock 또는 한 thread만 소유하게 하는 owner confinement가 필요하다.
  • workload trace: production에서 size 분포인 histogram, push/pop 비율, 짧은 시간에 몰리는 burst, p50/p95/p99, allocation/GC pause를 관측해 synthetic benchmark를 갱신한다.
  • portability: CPython version·allocator·hardware가 바뀌면 재측정한다. 언어 명세와 구현 세부를 문서에서 분리한다.
Anti-pattern: 다른 오류 semantics를 가진 구현 비교, 데이터 생성·print·assert를 timed region에 포함, 한 번만 실행, 평균 하나만 보고 tail 무시, GC 정책 미기록, getsizeof shallow 값만 합산, microbenchmark 승자를 profiling 없이 production에 교체, Big-O가 같으니 성능도 같다고 단정.

13. 대기업 면접 질문 3개와 답변 포인트

  1. 둘 다 O(1)인데 array stack이 더 빠를 수 있는 이유는?
    array push는 amortized O(1)이고 occasional resize가 있지만 대부분 reference write다. linked는 매번 Node allocation·추가 pointer·indirection이 있고 locality가 약하다. 점근 복잡도 밖의 상수를 말한다.
  2. 공정한 자료구조 benchmark를 어떻게 설계하나요?
    ADT semantics와 correctness를 먼저 고정하고 같은 trace·data·runtime·GC를 사용한다. setup을 분리하고 warm-up/repeat, 분포·tail·memory를 기록하며 production trace로 검증한다.
  3. linked representation을 선택할 조건은?
    Node handle을 통한 O(1) splice, stable identity, contiguous resize 불가, worst-case copy 금지 같은 요구가 실제 ADT에 있을 때다. 단순 Stack에서는 head push/pop 외 장점이 노출되지 않으므로 array가 보통 단순하다.
